Фаза 18: вход и оболочка варианта A

Откуда фаза · цель, требования, решения до неё The teacher signs in with an ielts-style account and works inside the variant A shell; student accounts can be created and deactivated. Sessions are stored in Postgres with hashed tokens; five failed sign-ins per login and IP within 15 minutes block further attempts for 15 minutes. Every screen uses Base UI components and variant A tokens, works in light and dark theme, and all text is in English. Радикс не используется: берём компоненты варианта A (Base UI) и пишем экраны заново. Интерфейс целиком на английском. Api — отдельный процесс за прокси. В web нет route.ts с монтированием api. Приложение и миграции идут под ролями без прав суперпользователя.

Api владеет аккаунтами и сессиями; браузер держит одну cookie.

Решаю сам, как в ielts. Сессия 30 дней с продлением. Web смотрит только форму cookie, настоящая проверка в api. Пароли — scrypt из node:crypto. Неверный пароль и неизвестный логин выглядят одинаково, блокировку человек видит.

Одна таблица accounts; одного активного учителя гарантирует индекс базы.

Почему важно. Критерий 1: второй активный учитель отклоняется базой. Деактивация повышает auth_epoch и удаляет сессии: ученик выходит везде.

Пароль ученика генерируется и показывается один раз; можно ввести свой.

Как задаётся пароль нового ученика?

Учитель меняет пароль, вводя старый; остальные его устройства выходят.

Как работает смена пароля учителя (ACCT-05)?
Смена пароля тогда не отзывает украденную сессию; выход везде работает только при деактивации.

Пять неудач на пару «логин + IP» за 15 минут закрывают вход на 15 минут.

Почему важно. Критерий 3. Api стоит за Caddy, поэтому IP берётся из заголовка прокси, которому api доверяет только в этой цепочке.

Кроме правила roadmap действует общий потолок на логин с любых адресов.

Добавить общий потолок на логин со всех IP?
Чужой человек может заблокировать вход самому учителю, перебирая его логин. Блокировка снимается сама через 15 минут.

Оболочка берёт компоненты и токены варианта A; экраны пишутся заново, текст английский.

Открывает палитру по клику и по ⌘K. Содержимое приходит в фазах 20–23. Решаю сам. Палитра знает разделы, смену темы и выход; поиск учеников и «New chat» добавит фаза 23. Тема по умолчанию как в системе, переключатель в верхней панели. В разделах без данных одна строка «Nothing here yet».

Копируем готовые компоненты варианта A и переводим подписи.

Откуда берём компоненты оболочки?
Токены и размеры шрифтов варианта A пришлось бы воспроизводить вручную; срок фазы растёт.

Первого учителя создаёт скрипт на сервере; ученик видит минимальную страницу.

Решаю сам, как в ielts. Скрипт идёт в образе api под ролью приложения, печатает сгенерированный пароль один раз и отказывается, если активный учитель уже есть. В репозитории ни адреса, ни пароля.

Ученик после входа видит страницу с именем и кнопкой выхода.
