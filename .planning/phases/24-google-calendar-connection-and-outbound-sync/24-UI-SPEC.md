## Surface and Interaction Contract

### Settings → Google Calendar

Добавить одну вкладку `Google Calendar` после `General`, URL `/settings?tab=calendar`. Не добавлять Assistant или Account/Appearance. Прямой переход и refresh сохраняют вкладку; ошибочный tab использует существующий General fallback. Заголовок `Settings`, затем Tabs, колонка max-width 720px с gap 16px. Порядок: Connection, затем Sync при существующем подключении. Не монтировать Phase 25 UI: Live updates, Last full check, Events to review, Assign/Ignore и rule card с Google wins. Скрытые функции не показываются даже как disabled controls или фиктивные статусы.

Connection — Panel `Google Calendar`, описание из C01 ниже. На desktop статус слева, действие справа; при узком экране действие переносится под текст. Connected показывает C02 и фактический `connection.calendar.label` основного календаря. Selector и смена target отсутствуют. В DTO нет account email: не выводить `Connected as…`, не угадывать адрес из app login/calendar ID и не добавлять identity scopes. Calendar ID остаётся технической identity; его не показывают и не пишут в browser logs. Неверный или неполный snapshot даёт ReadError, а не выдуманную подпись.

Sync — Panel `Sync` с описанием `Changes sent from the schedule to Google Calendar.` Простой список строк `Waiting changes` и состояние отправки. `pendingCount` считает distinct current connection sync-intent rows без полного acknowledgement, включая paused/failed; coalesced edits дают один target, wake-up jobs не считаются изменениями. Многоэтапный transition остаётся pending до завершения всех стадий. `None` разрешено только при достоверном нуле. Не вычислять число из уроков браузера. `sync: null` при `not_connected` скрывает Sync, но не означает удаление сохранённых intents. Ошибка чтения → C12/ReadError, а не None. Не вводить progress percentage, last-received/full-check timestamp, Sync now или второй writer в браузере.

### Binding to safe API contracts

Владелец будущих DTO — `packages/contracts`, источник контракта — RESEARCH §8. Ниже binding представления, не копия схемы. Сигнатуры ещё не реализованы. Все запросы web идут через `apiRequest`; пути указаны без proxy prefix `/api`.

| Contract / field                                      | UI binding                                                                                                                            |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /google/connection` → `GoogleConnectionSnapshot` | Один согласованный server snapshot; loading/read failure не являются успешными DTO                                                    |
| `asOf`                                                | Время snapshot для проверки его актуальности; не использовать как Last full check или last received timestamp                         |
| `connection.state`                                    | `not_connected`, `connected`, `reconnect_required`, `permission_required`, `disconnecting` → состояния таблицы ниже                   |
| `connection.calendar`                                 | `{ id, label, timeZone }` либо null; label — plain text основного target, timeZone — IANA metadata; null только для not_connected     |
| `connection.issue`, `sync.issue`                      | Только `CalendarIssue`; contextual mapping ниже, без provider text или raw DTO                                                        |
| `sync.state`                                          | `idle`, `queued`, `writing`, `paused`, `error`; отдельная ось, не доказательство подключения                                          |
| `sync.pendingCount`                                   | Неотрицательное число intents по определению выше; при paused/error сохраняется актуальное число                                      |
| `POST /google/disconnect`                             | Teacher/Origin-protected control operation; подтверждение C24; дальнейший progress через GET snapshot                                 |
| OAuth callback                                        | Фиксированный `/settings?tab=calendar` и выбранный сервером безопасный outcome; новый GET доказывает состояние, не success flag       |
| `POST /google/conflicts` → `GoogleConflictResult`     | Только полный результат: `inputKey`, `checkedRange`, `complete: true`, `conflicts`; error/incomplete идут normal typed API error path |

`CalendarIssue` mapping: `consent_denied` → C04; `invalid_callback` → C06; `scope_missing` → C05 при consent, C26 при потере доступа; `wrong_calendar` → C27; `provider_unavailable` → C07 при consent, C12 при status read, C13 при outbound error; `external_change` → C28; `write_failed` → C13; `disconnect_failed` при `disconnecting` → C09. Ошибка сессии следует существующему auth flow/C08, не выдуманному CalendarIssue. При неудачном новом consent прежний валидный snapshot остаётся основой состояния; banner описывает последнюю попытку, а не отменяет прежнюю связь.

### Allowed connection and sync states

Названия строк ниже — UI presentation; wire values заданы RESEARCH §8 и binding выше. Connection и sync — разные оси: действующий token не означает, что очередь уже пуста.

| State                                        | UI / actions                                                                             | Transition and truth                                                                                                        |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Loading                                      | Skeleton карточки; `Loading connection…`; Connect/Disconnect отсутствуют                 | До чтения snapshot нельзя показывать Not connected                                                                          |
| Read failed                                  | ReadError `Could not load Google Calendar`; Refresh                                      | Вкладка не подменяет ошибку пустым подключением; General остаётся доступен                                                  |
| Not connected                                | C01 + primary `Connect Google Calendar`                                                  | `connection.state=not_connected`, calendar/sync null; сохранённые внутренние intents/mappings этим не удалены               |
| Starting consent                             | CTA `Opening Google…`, loading, disabled повторный click                                 | Один переход в серверный OAuth flow, тот же tab/browser context                                                             |
| Consent returned / verifying                 | `Checking Google connection…`, skeleton/status                                           | Connected появляется только после серверного подтверждения; не по query string                                              |
| Connected, idle                              | Check-circle + C02; Sync `Waiting changes: None`                                         | `connected` + `idle`, pendingCount=0; не обещание inbound sync                                                              |
| Connected, queued / writing                  | C02; C10/C11                                                                             | `connected` + `queued`/`writing`; локальное сохранение не ждёт Google                                                       |
| Connected, sync error                        | C02 остаётся; error Banner C13 + `Refresh status`; известное pending count сохраняется   | Refresh читает состояние; не повторяет insert и не объявляет token revoked                                                  |
| Expired or revoked                           | Warning C03, primary `Reconnect`; C10/C30                                                | `reconnect_required` + paused work, bound calendar сохраняется; то же состояние над расписанием                             |
| Calendar permission lost                     | Warning C26 + `Reconnect`; C10/C30                                                       | `permission_required` + paused work; не называть это истечением token                                                       |
| Different account/calendar on reconnect      | Error C27; прежняя связь сохраняется                                                     | `wrong_calendar`; повтор с исходным аккаунтом; target не заменяется                                                         |
| Consent cancelled / failed / unsafe callback | C04–C08 над предыдущим достоверным состоянием                                            | Не стирать прежнюю связь оптимистически; безопасный повтор начинается из Settings                                           |
| Disconnect confirming / submitting           | ConfirmDialog C24, focus Keep connected, primary confirm; `Disconnecting…` во время POST | Keep connected до отправки ничего не меняет; accepted operation закрывает dialog и показывает server progress               |
| Disconnecting                                | C31; C10/C30; Connect/Reconnect/Disconnect disabled                                      | `disconnecting` с paused work; dispatch остановлен, revoke/clear ещё не завершены                                           |

Для reconnect использовать тот же server flow и только прежний bound calendar. При успехе C14, затем queued/writing/idle по фактическому snapshot; сохранённые intents продолжают отправку актуального состояния и незавершённые transitions. Не обнулять pending count на возврате из consent. Initial connect использует фактический primary calendar; последующие попытки не меняют identity. `Retry disconnect` повторяет ту же подтверждённую control operation через POST, не требует нового выбора disposition; Refresh только читает snapshot. При потере ответа POST показывать C32 и читать GET: нельзя утверждать stop dispatch, failed revoke или complete до server snapshot. Активный callback/reconnect не обходят generation-bound disconnect. API/queue recovery остаётся серверной ответственностью.

### Schedule banner and local saves

При expired/revoked вывести C03 над week grid, а на narrow — над day list, с `Reconnect`. Для permission_required использовать C26; для disconnecting — C31, при failed revoke — C09 с переходом в Settings. Banner не заменяет расписание и не отключает локальное создание/перенос/отметки. При подключении с sync error использовать C13 в том же месте. Ошибка Calendar status не должна выдавать исправное подключение; показывать C12 с переходом к Settings. Не показывать warning для обычного Not connected без попытки Calendar check.

Сохранение урока сохраняет существующие CTA/toasts (`Add lesson`, `Add series`, `Lesson added`, `Series added`, `Move lesson`). Они означают сохранение в dv-lab. Нельзя писать `Synced` или `Saved to Google` по факту локального ответа. Идемпотентность, recurring/instance/cut mapping и порядок записей — server contract SC2–SC3; новых управляющих этими механизмами UI controls нет.

### Conflicts while planning a lesson or series

Использовать существующий warning Banner над полями NewLessonDialog и соответствующих move forms. Это расширение существующей проверки, не новый экран. Локальные overlaps и Google conflicts имеют различимые заголовки; локальная ошибка не маскируется Google success. Предупреждение не блокирует сохранение (принятое правило v40). Ни ошибка проверки, ни загрузка не должны выглядеть как отсутствие пересечений.

Проверять candidate interval для одиночного урока и все вхождения в явно показанном окне для серии. Для серии с концом использовать весь её заданный диапазон. Серия без конца требует явного поля `Check through` под Repeats: DateField с helper C25, пустым исходным значением `Choose date`, min = дата первого проверяемого урока. Дата задаёт включительно последний день проверки, а не конец серии. Пока дата не выбрана, Google check не выполняется, UI показывает C25 и не утверждает отсутствие конфликтов; сохранение по принятому неблокирующему правилу доступно. При выборе/изменении даты запускается проверка полного диапазона, предыдущий результат устаревает. Скрытого default horizon нет. Текущий DateField требует непустую строку: planner должен явно включить безопасное empty state существующего поля либо его Calendar/Popover composition, не передавать пустую строку текущему formatter.

Отображать `Checked range: {from}–{to} ({zone}).` для завершённого результата. Границы относятся к полному запрошенному окну, не к первой Google page и не к первому уроку серии. Backend преобразует выбранные границы в конечный интервал и включает полный конец каждого проверяемого урока. Подписи границ и включительность конца должны совпадать с его completeness contract. A2 исследования закрывается этим явным вводом; бесконечного обещания нет.

Binding `GoogleConflictResult`: принимать только ответ текущего `inputKey`, совпадающий с validated projection формы; `complete: true` допускается только после всех Google pages и всех candidate intervals. `checkedRange.startsAt` включителен, `checkedRange.endsAt` исключителен, `displayTimeZone` задаёт подписи. Показывать фактические границы из ответа, не вычисленный браузером горизонт. Сервер фильтрует по объединению интервалов уроков: событие между еженедельными уроками не становится конфликтом только потому, что лежит внутри общего span. При error/incomplete нет частичного `GoogleConflictResult`; UI использует C20, а не фальшивый complete.

Каждая строка `conflicts` использует `id` как key, `title` как plain text или Busy, `interval` как `GoogleConflictInterval`. Для `kind: timed` показать startsAt–endsAt в основной зоне. Для `kind: all_day` показать startsOn и последний включённый день перед endsBefore с учётом календарной timeZone; endsBefore исключителен, не рисовать дополнительный день. Длинный event interval раскрывается целиком, включая соответствующие даты пересечений. `conflicts.length` определяет singular/plural и количество строк; web не раскрывает recurrence заново и не запрашивает следующие Google pages.

### Time-zone dependency (Phase 21.1)

Использовать будущий `TeacherSettings.defaultTimeZone` для новых inputs и UI labels; `ScheduleSeries.timeZone` и `ScheduleLesson`/`ScheduleBlock.timeZone` — сохранённая зона создания. `startsAt` остаётся instant. Смена default меняет подписи, а не время уже существующего события. `originalOn` occurrence ref — natural date rule zone; не вычислять его из отображаемой даты. После cut новые refs относятся к новому rule; UI не рисует старое и новое вхождение как два урока.

Conflict times показываются в account default zone; в компактном предупреждении достаточно одной зоны, как в NewLessonDialog, а существующий помощник Start time продолжает показывать вторую. Не жёстко кодировать VN, серверную зону или UTC offsets. Даты checked range включают год, если диапазон пересекает годы. Manual DST gap даёт явную field error, fold использует первый instant, recurring gap пропускается по стабильному контракту 21.1. Реализация этих правил ещё не подтверждена; не создавать локальный recurrence engine в web.

### OAuth error boundary
