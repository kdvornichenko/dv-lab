## Что сделано

- Блок `action_link`: один `<a>` (surface-3, shadow-2, radius-2xl, от 56px, плитка 32px с иконкой, заголовок `body` 600 до двух строк, строка `caption muted` с многоточием, стрелка). Ховер 5% и нажатие 9% делает слой `before` поверх поверхности (фон поверхности не заменяется), стрелка при ховере становится `foreground`, фокус 2px `focus-ring`, ничего не двигается. Заголовки и строки по таблице README: `Open Anna K.'s payments` / `Payments · Anna K.` или `Payments · Record payment`, `Overview · Edit details`, `Open Wed 14 Oct in the Schedule` / `Schedule · Week of 12 Oct`, `Open Settings` / `Settings · Assistant`. Адрес собирает `actionLinkHref` из полей контракта. Блок без страницы (нет `studentId` или имени у блока про ученика, дата не календарная у `schedule_day`) не рисуется (`null`). `dialog` попадает в адрес только в паре: `payment` с `payments`, `details` с `overview`, иначе отбрасывается. Явный case в `Block()`. Порядок блоков в UI не пересортировывается: сервер ставит `action_link` первым среди блоков конца хода (перед отказом и `suggestions`, после фактов, дат и результата).
- Профиль ученика: `page.tsx` читает `searchParams` и отдаёт `StudentProfile` разобранный `arrival` (`profile-arrival.ts`: `tab` из overview, notes, vocabulary, payments; `dialog` из payment, details; `entry` только UUID; `section` только из `SECTION_KINDS`; всё остальное игнорируется). Стартовая вкладка: `dialog=details` даёт Overview, `entry` или `section` дают Notes (все разделы живут на Notes, `tab` в таких ссылках игнорируется), иначе `tab` или Overview.
- Диалоги: после первого успешного чтения ученика `reload()` один раз разбирает запрос. `payment` открывает Record payment (ученик подставлен, значений нет, первое поле в фокусе, как у кнопки); `details` через пропс `autoOpenEdit` открывает Edit details с текущими значениями. Если открыть нельзя (ученик не найден, у ученика нет начального баланса `balanceMinutes === null`), открывается вкладка без сообщения. Ошибка чтения запрос не тратит: он применится после Refresh. После разбора `dialog` убирается из адреса через `router.replace` со `scroll: false` (`withoutSearchParams` в `lib/arrival-mark.ts`), `tab` остаётся.
- Метки: `use-notes-arrival.ts` ждёт, пока прочитаны разделы и записи (оба не loading), 200 мс, затем ищет `[data-note-id]` (запись) или заголовок раздела `#section-<ключ>`; прокрутка к середине, пауза 80 мс, `startMark` из общего механизма ScheduleArrival (две пульсации, кольцо 2px, уход по клику, клавише, прокрутке или через 4 с, reduced motion сразу кольцо). Запись получает кольцо с заливкой 22% на пульсах, заголовок раздела только кольцо; на время метки ставится радиус 8px. Нет записи или раздела: вкладка открыта молча. `entry` и `section` убираются из адреса после попытки; смена вкладки до разбора отменяет метку и тоже убирает параметры. `?tab=payments` из блока фактов открывает вкладку Payments.

## Решения и отклонения, которые стоит проверить

1. Условие «нет баланса» для `dialog=payment` взято из задания и README (п. 50): при `balanceMinutes === null` диалог не открывается, вкладка Payments открывается молча. Кнопка Record payment в шапке при этом работает без баланса и api оплату принимает, то есть ссылка строже кнопки. Условие одно (`student-profile.tsx`, `reload`); если нужно открывать всегда, достаточно убрать проверку.
2. `section` всегда ведёт на Notes, даже если в адресе `tab=overview` (блок `excerpt` берёт вкладку из контракта). Поля Level и Goals на Overview (карточка деталей) метки не получают: метка ставится на разделы заметок.
3. Метка раздела ставится на заголовок `h2` (по README AgentLinks: «the section heading»), а не на всю панель: у панели кольцо заменило бы её тень на 4 секунды.
4. Если в одном адресе одновременно `dialog` и `entry`/`section`, второй `router.replace` берёт ещё не обновлённый адрес и может вернуть уже убранный параметр. Блоки такой адрес не строят, мер не принято.
5. Порядок блоков не сортируется в вебе, он полностью на сервере (`runs.ts`: `run.link` ставится перед блоками конца хода).
