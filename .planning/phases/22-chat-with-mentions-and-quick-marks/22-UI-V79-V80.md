## A. Поповер Effort (v79)

- `model-controls.tsx`: текстовой кнопки «Use default (...)» и строки под слайдером нет. В шапке справа от заголовка ghost-значок `RotateCcw` 24px (`muted-foreground`), зазор 4px до значка info, `aria-label` и тултип (200 мс по умолчанию в `Tooltip`) «Use default (Medium)». Значок всегда в разметке, при совпадении с умолчанием `opacity-0` + `pointer-events-none` + `aria-hidden` + `tabIndex=-1`; вход и выход по opacity за 160 мс, высота и заголовок не двигаются. Сброс не закрывает поповер (иначе уход значка не виден): отправляет `{ model, effort: null }` и ставит фокус на бегунок.
- Слово в шапке (`EffortWord`): кроссфейд на месте в одной ячейке grid, старое уходит 120 мс, новое входит 160 мс, блюр 2px, невидимый «Extra high» держит ширину. Reduced motion: обычный текст.
- `effort-slider.tsx` переписан без Base UI Slider (он позиционирует бегунок и заливку через `inset-inline-start` и `width`, что не даёт «только transform и opacity», и отдаёт только целые значения, поэтому «следует за указателем без плавности» на нём недостижимо). Свой слайдер: `role="slider"` на бегунке, `aria-valuemin/max/now/valuetext`, стрелки, Home, End, указатель с захватом. Бегунок едет `translateX`, заливка `scaleX` от левого края (плюс неподвижная 8px-заглушка слева), 160 мс `cubic-bezier(0.23, 1, 0.32, 1)`; точки гаснут 120 мс; метр в чипе заполняется 160 мс; при перетаскивании (после порога 3px) transition выключен, на отпускании бегунок доезжает до ближайшей доступной точки за 160 мс; нажатие на дорожку сначала едет с анимацией. Reduced motion: `motion-reduce:transition-none` везде. Недоступные уровни по-прежнему недостижимы (бегунок зажат между наименьшим и наибольшим доступным), `data-slot="effort-unavailable"` и тултип сохранены.
- Слайдер держит показанную позицию локально и отправляет изменения по очереди: пока запрос идёт, следующие значения сворачиваются в последнее (иначе удержание стрелки даёт 409 по ревизии). `onChange` может вернуть `Promise<boolean>`; `false` возвращает бегунок к последнему сохранённому значению. Карточка Chat model тоже возвращает результат сохранения.

Отличия от текста дизайна:

1. Enter закрывает поповер только с бегунка (раньше с любого элемента), иначе Enter не нажимал бы значок сброса.
2. Слово в шапке и чип меняются, когда сервер (или локальное состояние нового чата) отдаёт значение, а не мгновенно от указателя; при перетаскивании сохранение идёт на каждой смене точки (с сворачиванием очереди), поэтому слово следует за бегунком с задержкой одного ответа.

Ручка `GripVertical` 24px ghost, `cursor-grab`, тултип «Drag to reorder», имя «Reorder <model>», не рисуется при одной модели, выключена у строки с открытой формой; перетаскивать можно и за ручку, и за сводку (мышь и перо; кнопки внутри сводки не начинают перетаскивание). Клавиатура на ручке: Space поднимает, Up/Down двигают, Space/Enter кладёт, Esc возвращает снимок порядка; живая область `role="status"`: «Sonnet 5.5, position 1 of 4.» (при падении «..., dropped, position N of M.», при Esc «Reorder cancelled.»); уход фокуса на другой элемент или нажатие мышью кладёт строку. Новый порядок даёт «Unsaved changes» через существующую сигнатуру.
2. Close в форме модели: `variant="secondary"`, compact.
3. Budget (`budget-usage.tsx`, подключён в `assistant-card.tsx`): строка «$X used» (600) слева и «$Y left» справа, полоса 8px на `selected`, сегмент на разговор (`flex-grow` по стоимости, `gap-0.5`, `min-w-[3px]`), цвет `primary`, от 80% `warning`, от 100% `destructive` (полоса полная, «$0.00 left»), штрихованный сегмент для удержанного запросом с подписью «$0.40 is held by a request in progress.», подпись оценки или строка с info «Usage has not been confirmed. The figures are estimates.», ниже таблица «Usage by conversation» с «Other conversations»; наведение на сегмент или строку подсвечивает пару, тултип с разговором и суммой. Расчёт идёт от лимита из поля (черновик, если он верный), поэтому полоса красится, когда новый лимит ниже расхода. Атрибуты `data-budget-usage`, `data-budget-conversations`, `data-budget-note`, `data-budget-fill` (процент, 100 при красной) сохранены.

## Чего не хватает в api (не менялся)

`GET /settings/assistant` отдаёт `usage` только по пяти крупнейшим разговорам (`USAGE_ROWS = 5`), а `costUsd` разговора включает удержание (резерв) незавершённых запросов, тогда как `spentUsd` бюджета его не включает. Поэтому:

- сегменты: пять разговоров и один общий сегмент «Other conversations» (остаток `spent + held - сумма строк`), а не сегмент на каждый разговор месяца; для полной раскладки api должен отдавать все разговоры периода (или хотя бы их число и суммы мелких);
- пока идёт запрос, стоимость разговоров масштабируется на `spent / (spent + held)`, чтобы удержание не считалось дважды (отдельно хатчем); для точной раскладки api нужно отдавать для каждого разговора settled и held отдельно.
