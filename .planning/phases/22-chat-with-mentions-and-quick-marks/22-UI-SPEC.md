## 5. Conversations, mentions и quick actions — UI1/UI2

### Conversations

New chat создаёт conversation metadata без paid model invocation. Initial title New chat; автозаголовок не требует отдельного AI call (**UD6, unreviewed default**). List rows показывают title, время и preview последнего сообщения либо Empty chat / Waiting for a decision из фактического run state. Статус list loading/error не создаёт новую conversation и не очищает выбранную.

Rename — labelled TextField, Keep title / Save title; Keep title закрывает dialog с прежним saved title, Save title сохраняет новый title через прежнего owner. Strict chat schema задаёт finite title/message/context limits, overflow показывает validation error без silent truncation. Draft сохраняется при ошибке, pending Save title disabled. Delete conversation — прежний ConfirmDialog, Keep conversation / Delete conversation, initial focus Keep conversation, body P04. Keep conversation закрывает dialog и сохраняет chat. По R9 P8/F08 server success означает removal from active reads и redaction chat content/mentions; noncontent usage/control liabilities сохраняются. Lessons/notes/marks/Calendar changes не каскадируются; delete не отменяет ongoing provider request. При unresolved run/mutation/usage uncertainty delete disabled с P05 до известного исхода (**UD6**). Это не обещание immediate backup/provider erasure; actual privacy/storage handling требует evidence до shipping. CHAT-01 не разрешает student/payment deletion.

### Mentions

`@` в начале или после пробела открывает literal normalized displayName search из R9 P3/F03; существующий owner не имеет handle column. Arrows, Enter/Tab выбирают, Esc закрывает только popup. Selection вставляет видимое имя и сохраняет точный server-resolved studentId через MentionBinding; wire schema имеет одного contracts owner. Text edits инвалидируют affected mention binding, не переносят ID на новый текст. Focus остаётся в textarea. Typed unresolved @text не выбирает первого кандидата. Duplicate names требуют явного selected ID и safe secondary distinction. Server повторно проверяет teacher/card/binding при Send; rename/removal/inactive card требуют актуального выбора, имя не является устойчивым ключом.

Empty results — No students found / Try a student name. Search выдаёт до шести safe candidates со stable lower(displayName),id order по server owner; UI не загружает full card facts на каждый keypress. Loading/error отличны от empty; query сохраняется. Enter при открытом list выбирает item без Send; без list Enter отправляет, Shift+Enter добавляет строку. IME composition Enter не отправляет. Failed admission сохраняет draft; accepted Send создаёт один persisted teacher message. Same requestId/body читает original outcome, changed body отвергается; reconnect не создаёт второй message.

### Result и Undo
