### Месячный предел — $10 по умолчанию (решение владельца 2026-10-13, В9)

Предел — настройка учителя `chat_monthly_cap_usd` (22-11, десятичная строка USD), начальное значение **$10 в месяц**, учитель меняет в Settings → Budget. Расчёт: быстрые формы и отметки модель не вызывают; на свободный вопрос уходит 1-3 запроса. Факт по тарифам 22-11 при ~10 000 токенов входа и ~1 500 выхода на запрос: Haiku 5.5 ≈ $0.002, Sonnet 5.5 ≈ $0.035, Opus 5.5 ≈ $0.07. Триста вопросов в месяц на Haiku — около $1-2, на Sonnet — около $20. Резерв одного запроса по верхней оценке (100 000 входа, 16 000 выхода): Haiku ≈ $0.021, Sonnet ≈ $0.41, Opus ≈ $0.82, Fable ≈ $2.05; при $10 и Fable 5.1 одновременно помещаются четыре резерва. Предел ниже суммы API-кредитов плана (ROADMAP Notes); остаток кредитов API не отдаёт, поэтому приложение его не показывает. Порог уведомления 80% — из ChatModelControls.

Попытка с неизвестным расходом (запрос мог уйти, usage не пришёл) не закрывает приём навсегда — её резерв остаётся удержанным в пределе месяца, и новые запросы принимаются, пока помещаются.

`chat/budget.ts` — единственный владелец денежных единиц и формул чата, по одной функции на формулу:
- `usdToNano(text: string): bigint` — десятичная строка USD (предел из настроек, тарифы записи модели) в целые нано-доллары без `Number`; `nanoToUsd(nano: bigint): string` — обратно для снимка бюджета и расхода по разговорам;
- `reserveNano(choice): bigint` = `ceil(maxInputTokens × max(inputPerMTok, cacheWrite5mPerMTok) + maxOutputTokens × outputPerMTok)` в нано (тарифы за 1M токенов, кэш промпта только 5-минутный, 22-13);
- `costNano(pricing, usage): bigint` — вход, запись кэша, чтение кэша и выход по захваченному тарифу, округление вверх.
Других мест этих формул в api и web нет; `settings.ts` хранит предел десятичной строкой и не переводит его (22-11).

- `reserveAttempt(tx, accountId, conversationId, choice, now)` (`choice` — результат `resolveModelChoice` 22-11: запись модели с тарифом, уровень, `maxInputTokens`, `maxOutputTokens`): зона учителя из `readTeacherSettings`, предел — `usdToNano(readAssistantSettings(...).monthlyCapUsd)` в той же транзакции; период текущего месяца: `INSERT … ON CONFLICT (account_id, starts_on) DO NOTHING`, затем `SELECT … FOR UPDATE` той же строки (две параллельные первые попытки месяца не падают на уникальном ключе; блокировка строки периода сериализует параллельные разговоры и вкладки); резерв = `reserveNano(choice)`; `spent + held ≥ cap` → `budget_reached`, `spent + held + reserve > cap` → `budget_insufficient`; иначе строка попытки `reserved` с захваченными тарифом и лимитами, `held += reserve`. Резерв коммитится до сетевого вызова. Снижение предела в Settings ниже уже потраченного даёт `budget_reached` со следующего запроса; принятые попытки не пересчитываются.
- `markDispatched(db, attemptId)` — перед отправкой запроса; `settleAttempt(db, logger, attemptId, usage)` — один раз: `cost = costNano(захваченный тариф, usage)`, `held -= reserved`, `spent += cost` по факту, даже если `cost > reserved`; при `cost > reserved` — строка лога уровня `warn` с id попытки, моделью, резервом, стоимостью и числами токенов, без текста; `state = 'settled'`; повтор — без изменений; `markUnknown(db, attemptId)` — запрос мог уйти, usage нет: резерв остаётся в `held`, `state = 'unknown'`; `release(db, attemptId)` — только для попытки, которая точно не ушла (`reserved`, не `dispatched`): `held -= reserved`, `state = 'released'`; её зовут бегун при отказе до сети и `sweepInterrupted` (22-13) для попыток `reserved`, оставшихся после перезапуска.
- `readBudgetSnapshot(executor, accountId, now)` и `usageByConversation(executor, accountId, periodId, limit)` — чтение, без вызова модели; предел снимка — из `readAssistantSettings`.
`routes/settings.ts`: ответ `GET /settings/assistant` и `PATCH /settings/assistant` (22-11) дополняется `budget: budgetSnapshot` и `usage: conversationUsage[]`; сохранение предела и проверка значений остаются у `saveAssistantSettings` (22-11).
Коды отказа бюджета (`budget_reached`, `budget_insufficient`, `credits_unavailable`) уже есть в `chatRefusalCode` (22-09); в `errorCodes` они не входят: это блоки чата, не HTTP-ответы.
