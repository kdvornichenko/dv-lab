## Что сделано

- **Контракты.** `calendarCommandOperation` и `operation`/`google_commands_operation_ck` содержат `event_create`, `event_update`, `event_delete`, `assign`. `validatedCalendarCommand`: `event_create { input: createCalendarEventCommand }` (запрос + `calendarCommandMeta`), `event_update { eventKey, input }`, `event_delete { eventKey, input }`. `assign` есть только в списках, член `validatedCalendarCommand` и обработчик добавит 25.1-09.
- **Значения базы.** `googleCommandInput` получил члены трёх операций событий (проверенный ввод без `requestId`/`expectedVersion` и id целевого события), `durationMinutes` в `move` и `move_series`; маркеры и `dvKind` принимают `event`; `googleOwnedPayload` и `googleEventFact` — необязательные `colorId`, `description`, `location`. Список записываемых полей перенесён из `command-result.ts` в `GOOGLE_WRITABLE_FIELDS` без изменения порядка; `ownedWritableKeys(payload)` возвращает принадлежащие запросу `colorId`, `description`, `location`. `googleUnownedWritable` не менялся.
- **Приём (`event-commands.ts`).** Только SQL: строка по `eventKey` (`rowByKey`), мастер (`masterRow`), версия `eventVersion(строки)`, окно синхронизации, незавершённая команда. Строка урока (`boundRowCondition`) — `invalid_request` при любой области. Не `default` — `read_only_event`; весь день — правка `read_only_event`, удаление только `one` (D-15); серия не weekly — только `one` и только время, иначе `unsupported_recurrence` (D-16). Создание: Once или `RRULE:FREQ=WEEKLY;BYDAY=..` через `masterRepresentation`, пояс по умолчанию, детерминированный id `dv…`, маркер `event`, строк уроков и сопоставлений нет. Правка: `one` — патч одиночного события или вхождения (`instance` с `lookupVerified: true`), one-off → weekly добавляет правило; `all` — патч мастера по etag мастера; `following` — обрезка UNTIL мастера и вставка нового мастера с изменёнными полями. Удаление: `one` — `status: cancelled`, `following` — обрезка UNTIL, `all` — мастер `cancelled`. Статус в правке не посылается, Tentative остаётся.
- **Отправка (`dispatch.ts`).** Для `event_update`, `event_delete`, `assign` — одно чтение цели: etag должен равняться `ifMatch`, у вхождения сверяются `recurringEventId` и `originalStartTime`, иначе `external_change` и команда закрывается неотправленной. База (`observedBaseline`) пишется в `cancellationBaseline` запроса стадии в транзакции `prepareDispatch`; компаньон `create_master` получает `preserved` из того же чтения. Ворота `canChange` — только для операций уроков. `preservesUnowned` берёт отпечаток предусловия плана, если он есть, иначе базу стадии; вставка без `preserved` допустима для `create` и `event_create`. `projectCommand` для событий пишет факты всех подтверждённых стадий `write` и `create_master` и зовёт `applyConfirmedEvent` (без строк уроков). Факт мастера из подтверждения теперь несёт классификацию повтора.
- **Проверка ответа (`command-result.ts`).** Отпечаток и снимок незатронутых полей считаются по `GOOGLE_WRITABLE_FIELDS` минус принадлежащие запросу ключи. `verifyRecurrence`: заданное повторение должно совпасть для любого вида; `event` без повторения в запросе и патч только маркеров на `series` его не проверяют; `single`/`occurrence` по-прежнему без повторения. Вид подтверждения `master` у `series` и у `event` с непустым повторением ответа. `status` сравнивается, только если запрос его несёт; `colorId`, `description`, `location` — если принадлежат запросу (через `eventDetails`), и попадают в подтверждённый факт.
- **Маршруты.** `POST /google/events` (202), `POST /google/events/:eventKey` (202), `POST /google/events/:eventKey/delete` (202), `GET /google/events/:eventKey` (детали из SQL, 404 при неизвестном, отменённом или мастер-ключе). Сессия и роль учителя — общие для `/google`.
- **Длительность.** `durationMinutes` (целое, от `LESSON_MINUTES_MIN`, без верхней границы) в `moveLessonRequest` и `moveSeriesRequest`. `cutSeries` принимает перенос только длительности; `prepareLessonChange` и `occurrenceChange` отказывают, только если не меняется ни начало, ни длительность; `applyOccurrenceChange` выбирает `restored` только при естественном начале и длительности серии; `applySingle` пишет длительность урока. Строки расписания не удаляются, правило серии не меняется — новая длительность серии через разрез.

## Отклонения от плана

### Исправлено по ходу

**1. [Правило 3] `packages/contracts/src/calendar-events.ts` вне списка файлов.** `calendar-events.ts` на верхнем уровне использует схемы `calendar.ts`; обратный импорт запросов событий в `calendar.ts` давал цикл с обращением к неинициализированной константе. Схемы `createCalendarEventRequest`, `updateCalendarEventRequest`, `deleteCalendarEventRequest` и `calendarEditScope` перенесены в `calendar.ts`, `calendar-events.ts` их реэкспортирует. Коммит c54245e.

**2. [Правило 3] `apps/api/src/calendar/journal.ts` вне списка файлов.** `preparedCommand` пропускал только шесть операций уроков; добавлены три операции событий (`assign` — в 25.1-09). Коммит e1d1ed2.

**3. [Правило 1] Отпечаток событий без `extendedProperties`.** Первый патч события из Google добавляет наши маркеры, и отпечаток ответа (`extendedProperties: {private: {}, shared: {}}`) не совпадал с базой чтения без ключа — любая правка такого события заканчивалась `external_change`. Отсутствующие `extendedProperties` теперь считаются пустыми. Отпечатки уроков не меняются: события уроков всегда несут маркеры, ключ у них есть. Коммит ac87556.

**4. Механика `following`.** План называл стадии `trim` и `create_master`. Обрезка мастера — основная запись kind `write` на стадии 0 (её читают `preparedCommand`, подтверждение и сверка), новый мастер — kind `create_master` на стадии 2 (стадия 1 занята чтением сверки `recovery.ts`). Вставка уходит первой, затем обрезка. Сбой обрезки после удачной вставки оставляет в Google дубль хвоста серии (виден после прохода синхронизации, удаляется пользователем); обрыв между двумя записями доходит до `failed` или `recovery_required` через существующую сверку, вставку она не повторяет. Обратный порядок терял бы хвост серии.

**5. Помощник пересчёта базы.** Вместо поля-функции на наблюдении (сломало бы строгий `googleObservedResource.parse` в разрезах уроков) — `observedBaseline(observation, payload)`: сырой ответ хранится в `WeakMap` по объекту наблюдения из `observeGoogleEvent`, форма наблюдения прежняя. Объект после `googleObservedResource.parse` — уже другой, его сырой ответ не найден.

**6. `occurrence-command.ts`, `series-command.ts`, `routes/schedule.ts` не менялись.** Первый уже брал длительность из `occurrenceChange`, второй переносит ввод с `durationMinutes` в план и берёт новое правило из `cutSeries`, маршруты читают контракты, где поле уже есть.

**7. Код отказа `from` на прошедшем или отмеченном вхождении — `409 precondition_failed`**, а не `lesson_changed` (так отвечает `prepareSeriesChange`). `schedule-mutations.ts` обрабатывает оба кода одинаково, правка web не нужна.

Миграция применена разовым скриптом из временной папки тем же способом (`node --env-file=<.env.test|.env> apps/api/src/migrate.ts` без `DATABASE_URL`/`MIGRATOR_DATABASE_URL`): `dvlab_test` — 15 записей журнала, `dvlab_dev` — 18 (в dev журнал длиннее числа папок ветки ещё до этого плана).
