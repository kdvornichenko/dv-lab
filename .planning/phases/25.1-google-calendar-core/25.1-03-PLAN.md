# 25.1-03 — Page reads become SQL over the projection

<objective>
Switch every page read (week, Today, Students, a student card) to SQL over the projection (D-19): no Google call, no lease, a version that changes only when the projection changes (SC7). Extend `calendarEventView` with the fields the grid needs (D-05, D-06) together with its producer.

Executor model: opus (read model, concurrency, contracts).

Purpose: completes the lock split of wave 1 for reads; from here the sync engine (25.1-06) is the only reader of Google events.
Output: `calendar/projection.ts`, rewritten `read-model.ts`/`read-state.ts`, routes without the provider refresh, `GET /google/sync` and `GET /google/colors`, the dev-stack launcher, the read acceptance script.

Known interim state (no release happens mid-phase): until 25.1-04 lands, lesson command preconditions and the history eligibility of marks still look at the old snapshot tables, so lesson commands and marks of newly confirmed lessons are refused between waves 2 and 3.
</objective>

Extend `calendarEventView` with required fields: `version: calendarVersion` (every event, not only lessons), `color: calendarEventColor`, `location: string | null`, `seriesMember: boolean`. The web only reads these, so its build stays green; any web compile error caused by an object literal typed as `CalendarEventView` is a stop-and-report.

`apps/api/src/calendar/projection.ts` (new; the only page-read access to `google_calendar_events` and `google_sync_state`):

- `syncFacts(executor, connectionId)` → the sync row or null;
- `weekRows(executor, connectionId, range)` → non-master rows with `ends_at` set whose `[starts_at, ends_at)` intersects the range (all-day rows included), cancelled rows included (the web hides cancelled plain events; cancelled lessons stay visible as today); a cancelled tombstone stored without times (25.1-01) is never returned, so nothing draws a block without an end;
- `nextRows(executor, connectionId, now, eventIds)` → the earliest future non-cancelled non-master row per bound event family;
- `rowByKey(executor, connectionId, eventKey)` and `masterRow(executor, connectionId, recurringEventId)` (used by later plans).

`read-state.ts`: keep `opaqueVersion`; `eventVersion` becomes `opaqueVersion([eventId, etag])` for projection rows (no global revision inside, so idle forms stay valid, research "How the week version grows"). Remove the per-request receipt WeakMap machinery once nothing uses it.

`read-model.ts`: rewrite `readCalendarWindow(executor, context, selection)` and `readNextLessons(...)` keeping their exported names and signatures; their callers (`today/today.ts`, `cards/card-facts.ts`) keep their calls and only change the path of their type imports in Task 3, because `reads.ts` is deleted in Task 4:

- connection snapshot via `readConnection`; only the current connection's rows are read (D-13);
- freshness from sync facts: `fresh` when the connection is `connected`, `last_full_at` is set, `issue` is null, the latest of `last_full_at`/`last_incremental_at` is within 5 minutes without an active channel or 65 minutes with one, and the requested range lies inside `[window_start, window_end)`; `fetchedAt` = that latest time; `revision` = `google_sync_state.revision`;
- outside the window (D-19): `last_known` with reason `outside_sync_window` and `write` blocked with the same reason; the rows still kept in the projection (bound lessons) are returned;
- stale or failed sync: `last_known` with `issue` or `provider_unavailable`; never synced or no sync row: `unavailable` (the contract refinement requires no events then);
- binding per row at read time with `loadMappings` + `bindEvent` (mapping by event id, then by recurring master id); drop the cancelled-tombstone helpers from the read path (the projection keeps cancelled rows itself);
- `editBlock`: transition and series rules as today; `read_only_event` when `event_type` is not `default`; `outside_sync_window` outside the window; plain `default` events get no block (they become editable once 25.1-07 accepts their commands; the web does not offer editing before 25.1-08);
- `color`: event `color_id` looked up in `palette` (background, foreground, `custom: false`); a `color_id` missing from the palette → `custom: true` with the calendar colour as background and the foreground null (D-05 stores no RGB of its own; v53 keeps a Custom colour read-only); no `color_id` → calendar colour; neither → all null (web falls back to `selected`, v53 GoogleEventBlock);
- `series` contexts: local series rows of mapped series visible in the range, version `opaqueVersion([mapping id, representation generation, series id])` (the master etag is checked at admission, 25.1-04);
- `readNextLessons`: `known` from `nextRows` inside the window; `none` only when the read is fresh (the window reaches 53 weeks ahead, D-19); otherwise `unknown`.
