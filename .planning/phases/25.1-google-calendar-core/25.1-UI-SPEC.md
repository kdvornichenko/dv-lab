# Phase 25.1 — UI Design Contract

> Visual and interaction contract for Google Calendar Core. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `25.1-CONTEXT.md` (locked D-01..D-12), `AGENTS.md`, design system `dv-lab-design` VERSION v52 (principles, component READMEs), current code in `apps/web/app/(app)/schedule/_components/`, `apps/web/app/(app)/settings/_components/calendar-card.tsx`, `apps/web/components/`.
> The archived Phase 25 UI-SPEC and the calendar-mirror delta were used as reference only. Their Settings "Events to review" list, guests, reminders, conference, attachments, all-day creation and a calendar selector in the event form are NOT part of this phase.
> Everything marked **proposed** is a default of this spec that the owner or Design dude has not reviewed. Everything under "Request Design dude" must be drawn before the plan that builds it is executed.

## Color

Neutral palette with one accent; surfaces from variant A tokens, light and dark.

| Role                | Value                                                  | Usage                                                                            |
| ------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Dominant (60%)      | `surface-2` (page, grid, dialogs' surrounding)         | Page, week grid                                                                  |
| Secondary (30%)     | `surface-3` panels, `surface-5` dialogs, `hover` boxes | Settings panels, dialogs, suggestion and description boxes                       |
| Accent (10%)        | `link` / `primary`                                     | See list below                                                                   |
| Destructive         | `destructive`                                          | Label of Delete event / Delete in confirmations, failure sentences. Never a fill |
| Warning             | `warning`                                              | Overlap control icon, stale/failed sync tint, 8px "needs a mark" dot             |
| Info                | `info`                                                 | 8px "matches a student" dot (proposed), info banner tint                         |
| Google event colour | resolved colour from the event or its calendar         | The one place where hue carries data (principles, 2026-10-09)                    |

Accent reserved for: primary button of a form (Add event, Save changes, Add lesson), the selected segment label weight (the segment fill is `active`, not accent), links in details (student name, Check status), today's date circle (existing). Nothing else.

Event colour rules (proposed defaults, Design dude to confirm):

- Block fill = the event's colour; if none, the calendar's colour; if neither is known, `selected`. Text is `gcal-event-ink` (#1d1d1d) or white, whichever has the higher contrast on the fill, chosen by one helper next to the block (not hard-coded per colour).
- The palette is read from the data (Calendar `colors` resource, cached). No eleven-colour constant in components. The tokens `--gcal-event-ink` and `--gcal-event-1..11` exist in the design `tokens.css` and are absent from `apps/web/app/globals.css`; the plan adds `gcal-event-ink` and the classic eleven only as the offline fallback when the palette has not loaded.
- Lesson blocks stay `selected` in this phase (AGENTS.md), so a coloured block reads as "not a lesson" at a glance. Status treatments (hatch for tentative, dashed, dimmed marks) stay on top of the colour and never replace it.
- Colour is never the only carrier of a state; the dot beside a colour name in the Color field is paired with the name.

## Screens and states

Laptop = 1440x820 (floor 1280x720); top bar 48px, the grid fills the window, no page scroll, no New button. Phone = 390 wide; below 768px the screen is the page header + toolbar + notice slot + grid frame (`h-112` today, `ScheduleAgenda` in the design; this gap is outside the phase).

Legend: **Exists** = reuse as is. **Extend** = existing code, new behaviour. **Request** = needs a drawing first (see the numbered list at the end).

### S1. Create any event (title, time, repeat, colour, place, description, calendar)

Entry (unchanged rules): click on an empty cell opens the editor at the pointer time, 60 minutes, with the frame left under the dialog; drag across empty cells opens it with the frame's range; mouse and pen only for drag. No New button and no keyboard shortcut on the laptop screen. On the phone the page header keeps one labelled button, renamed **New event** (proposed), opening the same dialog at the next whole hour.

Dialog: `Dialog` `lg` (540px laptop, 16px from the edges on phone), 24px padding, rows 12px apart, body scrolls with the fade and 4px ring room, title and footer fixed. The file `NewLessonDialog` becomes the shell of one dialog with a mode.

| Row | Lesson mode (Exists, unchanged)                                                                                                                                                                              | Event mode (Request 1)                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Segmented control `Lesson` / `Event` (Tabs look, 36px, selected segment `active`, weight 600). Opens on **Lesson** (proposed; no regression for the main flow). Changing mode keeps date, start, end, length | same                                                                                                                                                                                          |
| 2   | Student (Select, required)                                                                                                                                                                                   | **Title** (TextField, required, placeholder "Title"; no student, no card)                                                                                                                     |
| 3   | Date, Start, End (columns 1.25 : 1 : 1; helper lines carry the second zone)                                                                                                                                  | same                                                                                                                                                                                          |
| 4   | Length (HH : MM pair) and Repeats (`Once` / `Every week`)                                                                                                                                                    | same                                                                                                                                                                                          |
| 5   | -                                                                                                                                                                                                            | **Colour** (Select, 36px; row = 12px dot + name; first row "Default" shows the calendar colour; Request 8) and **Place** (TextField, optional), two columns 1 : 2 on laptop, stacked on phone |
| 6   | -                                                                                                                                                                                                            | **Description** (Textarea, plain text, 3 lines, grows to 8 and then scrolls inside; 24px line on touch)                                                                                       |

- Event mode adds no field beyond title, time, repeat, colour, place, description. Guests, reminders, conference, attachments, privacy and all-day creation are out of scope; the spec does not draw them.
- **Calendar** is not a field: D-04 puts the choice in Settings, so the dialog description names it: "Added to {calendar name}. Times are in {zone} time." (zone label of the default zone, "VN" until changed).
- **Repeats** offers exactly the rules the series model holds (weekly today: `Once` / `Every week`). The contract never shows daily, monthly or custom options. Other Google rules are only displayed (S3).
- **Colour** = the ready-made `Select` with a dot in each row (no swatch grid in this phase; proposed). Options come from the data. A colour the palette lacks is shown as a read-only row "Custom" with its dot and is kept untouched unless the teacher picks another.
- **Overlaps**: the automatic check of `GoogleConflicts` runs for Event mode exactly as for lessons (400 ms after the last valid change of date, start, end, length, or "Check through" for a weekly one; status on the left of the footer; popover on demand). Overlap warns and never blocks (D-09).
- **Footer**: left status (Checking…, Overlaps…, Check failed. Retry, Connect calendar, or the failed-save sentence); right "Discard changes" (ghost) and the primary **Add event** (weekly: **Add series**). Pending: "Adding…" with spinner, everything disabled. Add is never disabled by the check; it is disabled only when required input is missing.
- **Errors** (one per problem, under the wrong field): "Enter a title." (Title), "Choose a date." (Date), "Enter the length." (Length). Whole-form failure: footer sentence "Could not add the event. Try again." in `destructive` with the alert icon; values stay.
- **Success**: dialog closes, toast "Event added" / "{Title}, Wed 14 Oct, 18:00 VN." (series: "Series added" / "{Title} every Wednesday at 18:00 VN."), week refetches, scroll stays, no focus theft.
- **Writes blocked** (read not fresh, `write` blocked, unresolved commands): the grid does not open the editor (existing `editable` rule); the read-status button explains why.
- **Phone (390)**: one field per row, Start and End share a row; footer status on its own 28px reserved row above full-width 40px buttons; Description has a 24px line and no drag/resize anywhere.

**Delete** (Request 3):

### S7. Synchronization states (Request 7)

Honest rule: show only facts the server reports. No "Live updates", no "instant", no countdown, no percentages, no promised delay, no Sync now button, no copy about notifications or the nightly pass. The week updates itself after a server-confirmed change; no toast per background update.

| State (server fact)                                                            | Settings > Sync panel (new first line, `body`)                                                                               | Schedule                                                                                                                                                        |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Idle with a confirmed check                                                    | "Last checked Mon 12 Oct, 14:32 (VN)" in `muted-foreground`                                                                  | Read-status button as today (refresh icon `foreground`, tooltip "Last checked: … Refresh")                                                                      |
