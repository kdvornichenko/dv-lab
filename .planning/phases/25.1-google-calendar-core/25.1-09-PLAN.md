`schedule/inbound-apply.ts` (owned by `schedule`; called from `calendar`; it never imports `cards`) — research Pattern 8, under `lockSeries` / `lockLesson` in one transaction per entity:
- skip any entity with an unresolved command (the command's own apply decides; the next pass reconciles);
- an occurrence with a mark is frozen (D-08); only unmarked occurrences follow Google;
- single: start/end changed → `starts_at`, `duration_minutes`; cancelled → status `cancelled`; confirmed again → `scheduled`;
- instance: moved or resized → `moved` exception with start and duration; cancelled → `cancelled` exception; back at its natural time → `restored` (GCAL-08: one occurrence moves only that occurrence);
- master: `UNTIL` shortened → `endSeriesAt` (marked tail preserved); extended or removed → `ends_on` updated; weekday/time/duration/zone changed and still weekly → cut with `cutSeries` from the first unmarked future occurrence into a new `lesson_series` row and move the mapping to it (rule columns immutable, D-10); no longer weekly → end the series at the last past occurrence, future instances become plain events without suggestion; a new master carrying our marker for an existing series (Google "this and following" split, assumption A2) → cut at the split date and bind the new master to the new local series; deleted → as cancelled / `ends_on` at the last past occurrence;
- never deletes rows, never creates lessons for unbound events (D-07), never writes marks;
- if moving a mapping to a new series hits a database constraint that the existing columns cannot satisfy, stop and report the constraint name instead of changing the schema.
