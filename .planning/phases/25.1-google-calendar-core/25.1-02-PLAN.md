# 25.1-02 — Lock split and a configurable OAuth redirect for the local stack

<objective>

Executor model: opus (authorization, credentials, concurrency).

Purpose: the first wave removes the account-wide lock from everything a page does. The read path still calls Google until plan 25.1-03 switches it to SQL over the projection (that needs the tables of 25.1-01, built in the same wave); this plan already makes those calls lock-free.
Output: configurable redirect, `accessToken()` in credentials, three lease holders switched, R-08 narrowing, a lease acceptance script, a RUNBOOK section for stuck requests.
</objective>

- reads the current connection with `findConnection(db, accountId)`; add `db: Database` to the credentials deps and pass it in `apps/api/src/server.ts` (the only change there);
- refuses exactly as the lease wrapper does for not connected / reconnect / permission states;
- single-flight per account: an in-memory `Map<accountId, Promise>` so concurrent callers share one refresh;
- on refresh CAS loss (`persistRefresh` returned no row) re-read the row: if it is still `connected` with a newer `credentialGeneration`, drop the cache and use or obtain the winner's token; only if the row is no longer connected throw the matching fault.
