## Что сделано

- `projection.ts`: `upsertEventFacts(executor, target, facts, { seenEpoch })` сам считает `event_key`, `row_kind`, `starts_at`/`ends_at`/`all_day` (all-day через `startOfZonedDay`), пропускает строго устаревшие факты, ставит `seen_epoch` любой переданной строке, считает изменением только столбцы D-05 и поднимает `revision` один раз, если строка вставлена или изменена; без строки `google_sync_state` ревизию не трогает. Добавлен `syncRevision`.
- `event-mapping.ts`: `boundRowCondition(connectionId)` — активное сопоставление по `event_id`, сопоставление серии по `recurring_event_id` или наш маркер `single`/`series`/`occurrence`; `rowForLocal` — строка одиночного урока по сопоставлению, вхождения по сопоставлению вхождения или по `recurring_event_id` мастера и `original_start` как моменту времени.
- `read-store.ts`: остался `advanceCommandRevision` (проверка подключения, `requested_seq + 1`, возврат `revision`). `publishWindow`, `publishNext`, `mappingFingerprint` удалены, в `read-state.ts` удалены `recordRead`, `ReadReceipt`, WeakMap и `ReadEventRow`.
- `dispatch.ts`: нет обхода недели и основного календаря; `insert` проверяет только подключение, восстановление заменой оставляет `checkReplacement`. `projectCommand` блокирует строку подключения и пишет факты подтверждения (event, master, cancellation; у разреза — подтверждённые стадии записи) до применения.
- Приём: `create` без окна, обхода и основного календаря, `preconditions: []`, `baseRevision` = текущая `revision`; перенос, отмена, восстановление ищут строку через `rowForLocal` и требуют `expectedVersion === eventVersion(row)`, внутри транзакции строка перечитывается.
- `cancelled-*.ts`: вместо синтеза «надгробий» — отпечаток незатронутых полей из подтверждения последней применённой отмены (логика восстановления R2 сохранена).
- `history.ts`: отмеченное вхождение допустимо всегда; неотмеченное — без незавершённой команды и либо до `history_cutover_at` и существовало тогда, либо его строка проекции есть, не отменена, с `ends_at`, совпадает по началу и длительности и принадлежит тому же ученику.
- `instance-recovery.ts`, `recovery.ts`, `transition-proof.ts` (`verifyPrimary`, имя и сигнатура сохранены): сравнение только с календарём, состоянием и поколением строки подключения.

## Отклонения от плана

### Исправлено по ходу

**1. [Правило 3] `read-state.ts` вне списка файлов.** Приёмка задачи 4 (grep `googleReadEvents`) требовала убрать `ReadEventRow`; вместе с ним ушли `recordRead`, `ReadReceipt` и WeakMap, у которых не осталось вызывающих. Коммиты 5b4bef6, c643822.

**2. Задачи 2 и 3 связаны типами.** Форма цели `singleTarget` и цели вхождения меняется в задаче 2, а читают её модули наблюдения задачи 3, поэтому typecheck зелёный после c643822, а не после 32e495a.

**3. Версия серии.** План просил строить версию из версии контекста и etag мастера, но клиент держит `opaqueVersion([mapping.id, representationGeneration, seriesId])` без etag. Приём сравнивает с ней, а наблюдённый etag мастера — с etag строки мастера в проекции, если она есть. Иначе любая операция серии отклонялась бы.

**4. [Правило 2] Создание вне окна синхронизации** отклоняется `outside_sync_window` (D-19: недели вне окна только для чтения). Без строки синхронизации проверки нет.

**5. Пересечения без токена.** `checkCalendarConflicts` больше не вызывает `credentials.accessToken` (обновление токена — тоже обращение к Google): подключение из `findConnection`, свежесть из `syncRead`. Для `move_series` нет сверки мастера с правилом (раньше это было чтение Google), есть проверка версии контекста; исключается вхождение `editedRef` по ключу строки.

**6. `projectCommand` блокирует строку подключения перед записью фактов**, чтобы порядок блокировок совпадал с применением (подключение, затем строки).

**7. Смена поколения в проверке 1** смоделирована на приёме: обёртка `accessToken` отдаёт подключение со старым поколением, транзакция приёма с `FOR UPDATE` отказывает. Для проверки 4 время сдвинуто SQL (`history_cutover_at` на 30 дней назад, урок на сутки назад) и фактом через `upsertEventFacts`.

**8. `verifyPrimary`** сохранил имя и сигнатуру (его зовут `transition-verify.ts` и `transition-write.ts`), тело читает строку подключения из базы. Параметр `gateway` в нём больше не используется.
