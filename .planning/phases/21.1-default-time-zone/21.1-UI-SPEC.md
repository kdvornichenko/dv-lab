# Phase 21.1 — UI Design Contract

Контракт принятого дизайна Default Time Zone. Продуктовые решения: `21.1-CONTEXT.md`, D-01…D-08. Визуальный источник: локальная копия варианта A v40, включающая принятый в v37 дизайн зон. Порядок фаз: **21 → 21.1 → 24**. Пометки дизайна «after 23» не определяют порядок реализации.

## Scope and authority

- Результат: два отдельных Panel в Settings → General, подтверждение смены основной зоны и согласованное отображение времени во всех уже существующих поверхностях расписания, Today и карточек.
- В scope: Default time zone; существующая Second time zone; ZoneChangeDialog; динамические основные подписи; `Created in` в деталях; показ того же instant в другой зоне; границы даты и недели; состояния сохранения, ошибки и доступа.
- Вне scope: Account и Appearance, новые Google Calendar и Assistant tabs, OAuth, sync, чат, Stat/NextPayment, необязательная строка о сохранённой отметке при переносе, новые возможности wall-time picker. Никаких eyebrows.
- Текущая запись исследователя: только `.planning/phases/21.1-default-time-zone/21.1-UI-SPEC.md`. RESEARCH и ARCH-REVIEW принадлежат исследователю технической части; metadata — оркестратору. Этот документ не меняет API и source.
- Приёмка документа: каждый TZ имеет визуальный/поведенческий контракт и проверяемое E2E-наблюдение; новые продуктовые решения не вводятся; источники определены версиями и SHA-256. Независимый UI-check завершён; реализация ещё не проверена.
- A1: v40 содержит принятые карточки и подтверждение v37. Основание — VERSION и шесть README/preview ниже; опровержение — несовместимая новая версия этих файлов.
- Карта работ: источники и владельцы → соответствие TZ; состояния и даты → полнота контракта; E2E-матрица → наблюдаемая приёмка. Stop: UI-контракт одобрен независимым checker с явно указанным ограничением inventory.

## Typography

Четыре размера для добавляемого контента: **11, 12, 13, 16px**. Два веса добавляемого текста: **400 и 600**. Существующий PageHeader, числовые даты сетки и библиотечные controls сохраняют свою шкалу/variation settings; они не получают новую фазовую типографику.

| Role              | Size | Weight                                         | Line Height |
| ----------------- | ---- | ---------------------------------------------- | ----------- |
| Body / Label      | 13px | 400; заголовки What changes / What stays — 600 | 20px        |
| Caption           | 12px | 400                                            | 16px        |
| Heading (`title`) | 16px | 600                                            | 22px        |
| Micro             | 11px | 400                                            | 14px        |

Body: описание диалога, списки, пример, подписи полей. Caption: постоянная заметка, save/error caption, Created in label, form helper. Micro: второе время и headings favorites. `fontWeights.semibold` локальной библиотеки — variable weight 550, тогда как README заголовка требует 600. ## Layout and responsive contract

### Settings → General

Порядок в существующей колонке: Default time zone, Second time zone, Payments. Payments сохраняет свой компонент и поведение; изменение одной настройки не перезаписывает другую. У Settings остаётся существующий General tab и URL поведения; не переносить tabs будущих фаз из preview.

Обе zone cards используют Panel. Label/hint слева, field справа на desktop; постоянная заметка C04 только в default card. Footer каждой карточки явно называет место хранения. Подсказка C03 показывает текущее время **сохранённой** основной зоны и обновляется раз в минуту через существующий minute-now owner. Строк `UTC+N`/`GMT+N` на экране нет.

Ниже 768px label/hint и field стоят вертикально; поле занимает ширину карточки. На 320px viewport: page gutters 16px, карточка до 288px, внутренний field до 256px при Panel padding 16px. Тексты переносятся; горизонтального скролла страницы нет. General tab и существующий sidebar sheet сохраняются.

### ZoneChangeDialog

Порядок: title/description → What changes → What stays → optional Example → optional collision caption → error caption → footer. Title — первое содержательное имя диалога, без overline. Тело и footer не размещаются в отдельных вложенных cards.

На ширине ≥640px footer справа: Keep, затем Change, gap 8px, существующая высота Button 36px. Ниже 640px диалог отстоит от краёв на 16px; footer вертикальный, **Change первым**, обе кнопки full width, min-height 40px. Начальный фокус всё равно на Keep. Для длинного текста кнопка растёт по высоте, текст не обрезается.

На 320px диалог имеет ширину 288px и внутреннюю ширину 248px. Max-height `calc(100dvh - 32px)`; если содержимое не помещается, вертикальный scroll внутри диалога делает обе кнопки достижимыми. Центрирование сохраняется, внешнего горизонтального scroll нет. Title, списки, error и zone names переносятся. Example сохраняет цельные группы «time + label», перенос возможен около стрелки; на узком экране не держать всю конверсию в одном принудительном nowrap.

### Picker and long values

Default picker: field trigger, None запрещён, все поддерживаемые зоны доступны, включая вторую. Second picker: None разрешён, текущая основная зона и её эквивалентные aliases исключены по канонической идентичности. Совпадающая аббревиатура разных зон сама по себе не означает совпадения зон.

Popup на 4px ниже field, не уже trigger и не шире доступного viewport с 16px gutters; field popup — `surface-5`/`shadow-4`, строки min-height 36px. Toolbar сохраняет 280px popup, плотность 28px и `surface-4`, с ограничением доступной ширины. Список имеет внутренний scroll с существующим compact fade; остальные карточки не прыгают при его открытии.

Длинный IANA id в закрытом 36px trigger допускает ellipsis при сохранении полного accessible value. В popup полный id можно прочитать: перенос в строке с ростом её высоты, short label и star остаются доступны; не обрезать последние буквы label. Список, поиск по id/label/числовому offset, выбранная строка в видимой области, favorites и их порядок остаются у текущего компонента. Отключение второй зоны убирает её строку/колонку без пустого резерва.

### Stale state and permissions

API shape, version/precondition и код отказа принадлежат RESEARCH/ARCH-REVIEW. UI требует наблюдаемой границы: **устаревшее значение account zone не должно незаметно переинтерпретировать wall time при save**. Settings и открытая форма урока используют подтверждённый контекст. При обнаруженном stale состоянии показать C31 через существующий error pattern, не повторять mutation автоматически, дождаться refresh и нового осознанного действия. Refresh заменяет старую base zone; старую candidate нельзя молча подтвердить относительно новой base. Reload восстанавливает authoritative account value во всех разделах.

Если ответ save потерян, не объявлять успех и не менять localStorage предположительно. До повторной записи получить authoritative settings. Подтверждённый сервером результат может завершить успешный переход; определённый отказ оставляет старые значения. Механизм разрешения неопределённого ответа выбирает исследователь API. Нельзя обещать клиентский rollback уже зафиксированной серверной записи.

При reload/возврате из другого устройства main zone всегда приходит с аккаунта. Если сохранённая second совпала с новой main, известная предыдущая отличная main становится second; если её нет, использовать None согласно RESEARCH. Это fallback восстановления, не предварительный swap при неуспешной текущей mutation. Невалидное localStorage использует тот же distinct fallback; сетевой отказ не считается невалидной account zone. Первоначальное значение Moscow для нового браузера остаётся отдельным правилом и не подменяет восстановление после коллизии.

Teacher-only: существующий `requireTeacherPage` закрывает Settings; student уходит на `/`, истёкшая сессия — `/login?reason=expired`. API не выдаёт settings ученику и не принимает его mutation. При потере прав во время dialog не показывать success/swap; следовать существующему session/access handling. Не добавлять student settings UI и не отображать stale teacher payload после отказа авторизации.

### Keyboard and focus

- Label `Time zone` / `Second zone` связан с trigger; hint/error — с описанием этого же field. Toolbar сохраняет имя `Second time zone`.
- Popup использует существующий combobox: поиск, Arrow Up/Down, Enter для highlighted row. Esc закрывает только popup; это не отмена сохранённой настройки. Favorite star — отдельный Tab stop, Enter/Space меняет только favorite, popup и выбор сохраняются.
- ZoneChangeDialog — `role="alertdialog"`, имя от C14, описание от описания и двух списков. Focus trap, начальный focus на Keep, включая mobile с primary первой визуально. После cancel/success — возврат в default field.
- В pending focus остаётся внутри dialog, disabled buttons не вызывают обработчики, Esc/scrim игнорируются. При failure кнопки снова доступны; inline error доступен без закрытия/повторного открытия.
- Существующие focus-ring и reduced-motion поведение Dialog/Button сохраняются. Не вводить новую motion-систему и отдельный accessibility audit.

## Time display, occurrences and boundaries

### Main and creation zones — TZ-02, TZ-03

Account default управляет представлением и вводом новых уроков. Creation zone остаётся у каждого старого урока/серии. Смена настройки сама по себе не переносит instant, не режет серию, не переписывает weekday/time/исключения, не меняет keys и mark. `Created in` не означает дату создания и не является editable field.

Все текущие main labels и форматтеры получают main zone: Today date/rows, Schedule header/toolbar/agenda/grid/tooltip, Students Next lesson, профильный список уроков, LessonDialog, Whole series, New lesson/Move lesson/series helpers и preview, существующие подтверждения и toasts. Оставшаяся строка VN допустима только если конкретно показываемая зона действительно Vietnam, включая second/creation zone. Нельзя просто заменить буквы VN, сохранив старое число часов.

TimePair: main сверху; second снизу, 11/14 muted. В списках и Next lesson cell main line не добавляет label; headers/tooltips/sentences/helpers добавляют действующий main label. Toasts и confirmation questions показывают только main time с label. Если дата второй зоны иная, перед вторым временем стоит короткий weekday, например `Tue`, а не `−1d`; для range weekday относится ко всему диапазону. При переходе самого диапазона через полночь другая дата конца явно читается в details, без потери длительности.

`Created in` появляется только в LessonDetails и в доступном Whole series, если canonical creation zone отличается от main. Для одиночного урока тоже нужна строка в details. В details label рассчитывается на выбранный lesson instant; у Whole series — на reference occurrence. При равенстве зон строки нет. Не добавлять creation badges в cards, список уроков, grid, toast, field или toolbar.

Whole series показывает main weekday/time, вычисленные из ближайшего действующего вхождения в creation zone, и соответствующую second line. Числа stored weekday/time нельзя подписывать новым main label без конверсии. Созданное в другой зоне правило сохраняется; представление по следующему вхождению не обещает постоянное main wall time круглый год. При отсутствии будущего вхождения Whole series следует существующей доступности, без фиктивного ближайшего урока.

### Week and Today — TZ-03, TZ-04

Колонки недели, названия дней, сегодняшняя колонка, now-line и agenda определяются main zone. При смене зоны тот же instant может перейти на предыдущий/следующий день или неделю; occurrence отбирается по отображаемому времени, даже если его stored `originalOn` находится по другую сторону границы окна. Он не теряется и не дублируется. Группировка и учёт урока идут по дате начала в main zone; длительность и точные endpoints остаются в details.

Существующая геометрия WeekGrid сохраняется: 48px/час, 00:00–24:00, стартовый scroll около 08:00, переход между неделями сохраняет scroll, ниже `lg` — agenda. Gutter: две равные колонки по 36px, gap 8px, second слева, main справа; 100px с отступами 12px к краю и 8px к сетке. При None остаётся только main. Main label динамический; second reference offset/label — на понедельник показанной недели по принятому WeekGrid. Это reference axis, а tooltip/dialog каждой записи используют **её собственный instant**. Полчаса/четверть часа не округлять; в second midnight показывать weekday.

Today использует текущую дату account zone, включая заголовок, Lessons today и Earlier, not marked. Проверка `opening_balance_on` использует ту же дату урока, строго позже открытия. Смена даты около полуночи может изменить вычет и Pays soon; Today, Students и профиль после перечитывания должны совпасть. `paid_on` и сама дата открытия остаются date-only значениями, без конверсии через timezone. Правила Done/No-show, их коррекции и допустимость переноса прошлого урока сохраняются.

Детерминированный синтетический oracle для E07/E10: `2026-10-11T17:30:00Z` — Monday 12 Oct, 00:30 VN и Sunday 11 Oct, 20:30 MSK. Смена VN → Moscow относит этот же урок к предыдущим дню и неделе. При `opening_balance_on = 2026-10-11` отмеченный Done урок учитывается в VN и не учитывается в Moscow, поскольку новая дата равна дате открытия. Дата оплаты `2026-10-12` остаётся `2026-10-12`. Это ожидаемый результат будущей проверки, не evidence её выполнения.

### DST contract without new picker features

IANA zone, instant и текущий label — разные вещи. Settings hint/confirmation names используют текущую дату; lesson labels используют дату конкретного урока. Berlin может быть CEST или CET; длина label ≤4 capitals, без числовых UTC offsets. Если подходящей стандартной аббревиатуры нет, применяется существующее правило city-label.

Обычные недельные вхождения по обе стороны DST сохраняют wall time **в сохранённой creation zone**. В другой main/second зоне их часы могут отличаться на час. Каждое вхождение конвертируется отдельно; нельзя использовать один offset всей серии, недели или 24 часа как универсальную длину дня. Если offset меняется между началом и концом урока, оба endpoints в details показываются с корректными собственными labels; длительность остаётся реальным elapsed time.

Spring gap при ручном create/move и первом выбранном старте нового rule возвращает HTTP 400 `nonexistent_local_time`: форма сохраняет ввод, показывает error/helper, урок не создаётся. При autumn fold сохраняется первый, наиболее ранний instant; preview/helper явно сообщает о первом повторении и показывает его offset/label. Последующее weekly occurrence в gap пропускается; следующая неделя остаётся. Существующий instant во втором повторении часа не пересчитывается. Эти правила принадлежат `21.1-RESEARCH.md`; UI-SPEC не вводит offset selector, fold toggle, новый wall-time picker или второй самостоятельный алгоритм DST.

В отображении уже существующих instants повторный local hour не схлопывает записи: разные occurrences остаются отдельно доступны через существующий overlap layout/agenda; tooltip/details различают CET/CEST и даты. Невозможный local hour не порождает фиктивный сохранённый урок. Отдельные DST lanes и новая геометрия календаря не требуются.
