## Поведение и сигнатуры

- `timeZoneIdentity(value: string): string | null` использует Intl canonical identity. Сравнение не сводится к текущему offset.
- `TeacherSettings` содержит `paysSoonLessons` и `defaultTimeZone`. `UpdateSettingsRequest` выведен из strict nonempty schema.
- PATCH основной зоны требует `expectedDefaultTimeZone`. Независимый PATCH Pays soon не принимает эту precondition.
- `readTeacherSettings(executor, accountId)` возвращает полный settings snapshot. При отсутствии строки действуют существующий threshold default и Vietnam.
- `lockTeacherTimeContext(tx, accountId, expectedDefaultTimeZone?, now?)` возвращает `{ ok: true, context: { now, defaultTimeZone } }` либо `{ ok: false, error: 'default_time_zone_changed' }`. Account row блокируется до чтения settings.
- `saveTeacherSettings(db, accountId, input)` возвращает `{ ok: true, settings }` либо тот же failure. Upsert обновляет только переданные поля; stale отказ предшествует записи.
- `readSnapshot<T>(db, read)` принадлежит DB connection и сохраняет `repeatable read` / `read only`. Re-export в schedule отсутствует.
- Прежний `readPaysSoonLessons` пока нужен текущему Today. План 07 переводит этот consumer на полный context; после этого неиспользуемый export требуется убрать.
- HTTP guards, session-derived accountId, Origin, no-store и envelope сохранены. Copy stale409 соответствует UI-SPEC C31.
