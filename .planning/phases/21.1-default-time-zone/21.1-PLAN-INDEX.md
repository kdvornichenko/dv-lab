## Уточнения по независимому review

- R1 → 02:2/08:3: поздний настоящий ответ Pays soon обновляет только threshold. Zone save и second swap не откатываются полным старым settings response.
- R2 → 01:3/13:2: backfill совместим со старым runtime только до появления non-Vietnam stored zones. Внешний rollout закрывает новые записи до согласованного переключения API/web; после таких записей старый runtime не является допустимым rollback.
- D1 → 02:3/05:2: duplicate weekly matching включает canonical creation-zone identity. Разные зоны дают разные правила; старые rows не меняются.
- D2 → 02:3/04:2/05:1–2/06:1/08:2/09:1/10:2: core `nextSeriesReference({ rule, exceptions, now })` возвращает `{ originalOn, actualStartsAt: Date, ruleStartsAt: Date | null } | null`. `ScheduleSeries.referenceOccurrence` сериализует этот reference в ISO. Все `toWireSeries` callers передают его явно. Whole series использует natural `ruleStartsAt`; moved actual time не становится weekly rule. Полный future set читает rows в том же snapshot; web не раскрывает recurrence.
- P1 → 02:3: исторические midnight/skipped-day vectors читаются через week endpoint с соответствующим понедельником. Today использует реальный текущий account day в E10.

Эти уточнения не добавляют планов, файлов реализации, волн или внешних действий. Публичное поле `ScheduleSeries.referenceOccurrence`, экспорт core и явный аргумент `toWireSeries` принадлежат существующим owners планов 04–06; consumers — 08–10. Новые checks остаются внутри существующих durable E2E.
