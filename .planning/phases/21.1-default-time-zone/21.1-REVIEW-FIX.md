## Fixed Issues

### CR-01: Старая дата ответа становится датой новой оплаты после полуночи

Исправлено в `7ac9575`. `useScheduleFormContext` сохраняет зону открытия и stale-защиту, но получает текущий день через существующий `useMinuteNow`. Серверный `asOf` остаётся fallback первого server render. Минутный hook обновляется также на focus и visibilitychange. Значения payment/opening полей не переписываются.

Расширен существующий E10 journey: профиль и первая форма открыты до account midnight; после смены browser clock и focus уже введённая дата сохранена, следующий день доступен, новая форма выбирает новый день. Затем выбран date-only день, допустимый по реальным часам API, и оплата сохранена через UI, публичный API и настоящий Postgres. Повторный GET подтверждает сохранённую дату. Часы API не подменяются; этот тест не утверждает, что сервер пережил реальную полночь во время запуска.

Первый запуск (run 6) выявил неверное имя кнопки в новом шаге: изменённая форма показывает Discard changes. Тайм-аут закрыл request context до finally и оставил синтетические оплаты. Исправлен selector. Существующий cleanup owner теперь удаляет оплаты только явно зарегистрированных fixture cards перед удалением карточек. Recovery: removedOwnedFixtures=1, remainingOwnedFixtures=0, settings=restored. Повторные run 7/8 подтвердили teardown.

### WR-01: DST E2E зависят от того, что март 2027 года ещё не наступил

Исправлено в `92a560c`. Будущие weekly и reference fixtures вычисляют цикл America/New_York для года после текущего года из настоящего `/today.asOf`. Spring — второе воскресенье марта, fall — первое воскресенье ноября. Ожидаемые UTC instants, отмены, переносы и gap history используют эти даты.
