## Поведение и передаваемые сигнатуры

- `localTimeCandidates(date,time,zone): readonly Date[]` проверяет точный round-trip, сортирует уникальные instants. `zonedInstant` берёт первый candidate либо бросает `RangeError('nonexistent_local_time')`.
- `startOfZonedDay(date,zone)` использует первый midnight candidate; при отсутствии midnight ищет первый instant с civil date не раньше заданной. Окно skipped day пустое.
- `SeriesRule/SeriesTiming/SingleLesson/ScheduleBlock/Occurrence` содержат обязательную `timeZone`.
- `seriesStart` возвращает `Date | null`; `Occurrence.naturalStart` также nullable. Moved occurrence с реальным stored instant сохраняется даже при отсутствующем natural instant. Plan05 должен учитывать null при сравнении restore/move.
- `scheduleDate/scheduleToday/isAfterScheduleToday` требуют zone. `lessonDeduction/studentBalance/needsMark/todayCounts` получают последний позиционный `timeZone`; `markEffect` получает поле `timeZone`.
- `nextSeriesReference({rule,exceptions,now})` возвращает originalOn, actualStartsAt и nullable ruleStartsAt либо null. `nextLessons` использует тот же обход; gap не прекращает поиск.
- `cutSeries(rule,exceptions,change,{now,defaultTimeZone},marks?)` и `endSeriesAt(rule,exceptions,lastOn,{now,defaultTimeZone},marks?)` экспортируются через index из нового schedule-series owner.
- `seriesCutBoundary(rule,date,defaultTimeZone,'from'|'through')` возвращает instant и old naturalCutoff. Plan06 использует этот cutoff до загрузки хвоста.
- `CutSeriesResult` дополнительно включает `{kind:'nonexistent_local_time'}`: API должен преобразовать это в 400. Явно выбранный первый gap не переносится на следующую неделю.
- Prefix остаётся в old zone; новый rule хранит current main wall time; finite end сравнивается по exclusive instant. Exceptions/marks дедуплицируются по originalOn, detached lessons сохраняют old instant, duration, status и zone.
