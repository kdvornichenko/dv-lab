## 5. Durable preview → teacher decision → receipt — D1

R3 P1 связывает UI с proposed prepareProposal/confirmProposal/declineProposal/readProposal, final22 durable store и server-derived safe preview. Model identifies teacher spans/intent; server resolves IDs, exact values, ownership, eligibility and effect. Preview renders the same normalized persisted payload later dispatched. Waiting может писать только proposal metadata; business effect ещё отсутствует. Narrative completion claim удерживается до matching receipt.

Confirm привязан к actor/account/conversation/current proposal revision/digest, captured targets and versions; browser не заменяет amount, scope или payload. UI button — явная decision action. Free-text yes/approve, model/tool text, quoted records и essay не являются Confirm. Deleted conversation/declined/superseded proposals не дают позднего apply; rebind final22 deletion/pending-action gate. Preview/essay reuse final22 safe renderer: validated text/bold/line breaks/known blocks; raw HTML, arbitrary model links/actions и provider payload не исполняются.

| Presentation state                | Visible / enabled action                                                                         | Observable contract                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Preparing / read unavailable      | Existing working message or P20; decision absent/disabled                                        | No invented preview/empty target; safe reread, no business write                                  |
| Needs clarification               | Exact missing amount/currency/identity/date/zone/lesson scope question; composer retains context | Explicit teacher input → new server preview; model never guesses required values                  |
| Waiting for decision              | Full exact preview + P01; concrete primary/Decline pair from §6                                  | No autoaccept, timer expiry, optimistic balance or Saved                                          |
| Decision pending                  | Busy text for operation, aria-busy, both decisions unavailable                                   | Same decision identity; Confirm/Decline race has one server winner                                |
| Superseded / stale                | P12 + Refresh proposal; old buttons inactive; changed fields visible in new preview              | No first write from stale revision. New preview always requires new explicit Confirm              |
| Applying local change             | P11; proposal retained on reload                                                                 | Local effect + receipt atomic; repeated decision returns existing receipt, never new payment/card |
| Waiting for Calendar / projection | P15 + allowed Check status; actual per-target state                                              | Confirm alone is not Saved; matching writer ACK + committed projection required                   |
| Partial / recovery                | P16 + confirmed/unconfirmed/not-started breakdown; owner-supported recovery action               | Earlier effects retained; no overall Saved, rollback, clone or blind resend                       |
| Applied                           | Specific P10 result + structured normal-form link                                                | Matching local receipt or verified Calendar result only; current views reread same data owners    |
| Declined                          | P13; read-only preview/status retained                                                           | Only decision metadata changes; this proposal made no business change                             |
| Definitive no-effect failure      | Owner-confirmed P14, retained input and actual next step                                         | Retry/revised preview only when owner permits; HTTP timeout alone cannot prove no effect          |
| Outcome/status unknown            | P20/P15; Check status/Refresh status using original identity                                     | No new request identity/provider/tool replay from refresh or stream reconnect                     |

Confirm не требует model call: budget/model outage не блокирует решение уже подготовленного proposal и не переименовывает committed effect в model failure. New paid explanation/continuation проходит обычный22 admission. Original tool call получает persisted pending-proposal result до waiting decision; reconnect/reload читает stream cursor/proposal receipt, не повторяет generation/tool/payment. Stop reply сохраняет22 meaning: не Decline, Undo, rollback или no-charge; уже admitted business operation читается через owner status.

Canonical card сохраняется без four-second countdown/automatic close. Optional inherited success toast не заменяет receipt. Late unrelated inbound revision, model prose или другой action не подтверждают текущий proposal. New Phase23 operations проходят server propose allowlist; model не выбирает direct22 quick-action tool для обхода required confirmation. Accepted22 quick mark/note/Undo controls остаются по своему contract.

Source weekday/time is evaluated as wall time in the **command input zone**, not compared with stored rule strings from another zone. No browser recurrence expansion. Numeric offset here is selection evidence, not a replacement for normal zone labels. Exceptions/cut lineage come from final core/24 owner; do not copy the old unconditional Cancelled lessons are reset sentence.
