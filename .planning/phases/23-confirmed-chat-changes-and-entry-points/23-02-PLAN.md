# 23-02 — Ревизии карточки и оплаты, исправление оплаты той же строкой

<objective>
Ввести числовые ревизии карточки и оплаты (ARCH-A2) и исправление оплаты без удаления и повторной записи (ARCH-A1). Это владельцы для SC3: изменение из чата открывается в обычной форме и исправляется ею, обе дороги дают один остаток, и поздняя правка из другой вкладки не теряется. Предложение оплаты из 23-01 переводится на ревизию карточки.

Решения: D-03 (одни владельцы домена), D-06 (id и история сохраняются; оплата не пересоздаётся), принятые ARCH-A1 и ARCH-A2 из 23-ARCH-REVIEW.md. `expectedRevision` необязательна на проводе: e2e-помощники (`e2e/support/calendar-read-recovery.ts`, `e2e/support/test.ts`, `e2e/support/tz-ledger.ts`) и проверки (`scripts/dev-checks/chat-runs.mjs`, `ledger-api/context.ts`) пишут без неё и остаются зелёными; формы web начнут её посылать в 23-06.

Executor model: opus (CAS, деньги, совместимость с существующими проверками).

Purpose: без ревизий устаревшая полная форма карточки перезапишет ставку из чата, а исправление оплаты возможно только удалением.
Output: миграция `card_payment_revision`, ревизии в контрактах и владельцах, `PATCH /payments/:id`, проверка `cards-revision.mjs`.
</objective>

Контракты (`students.ts`): `StudentDetail.revision: number`, `PaymentRow.revision: number`. Поля карточки вынести в базовый объект; `saveStudentRequest` = база + refine пары ставки (как сейчас), `updateStudentRequest` = база + `expectedRevision: int ≥ 1, optional` + тот же refine (в zod 4 `extend` у объекта с refine не вызывать — расширять базу до refine). `openingBalanceRequest` получает необязательную `expectedRevision`; новый `cardRevisionRequest = z.strictObject({ expectedRevision: int ≥ 1 optional })` для архива и восстановления. Для оплат: `updatePaymentRequest` (`paidOn`, `amountMinor`, `currency`, `lessonsHundredths | null`, `note`, `expectedRevision` обязательна, `expectedDefaultTimeZone`), `paymentRevisionRequest = { expectedRevision optional }` для DELETE, `assignPaymentRequest` + необязательная `expectedRevision`. Новых кодов ошибок нет: конфликт — существующий `precondition_failed`.

Владелец карточки (`card-rows.ts`, `cards.ts`): `cardColumns` и `toStudentDetail` несут `revision`. Результат писателей — `{ kind: 'ok', detail } | { kind: 'not_found' } | { kind: 'changed' }`: `updateCard(executor, id, input, context, expectedRevision?)`, `archiveCard(executor, id, context, expectedRevision?)`, `restoreCard(...)` — условие `revision = expected` только когда ревизия передана, `revision = revision + 1` и `updatedAt` при каждой записи; «changed» отличается от «not_found» повторным чтением строки. `setOpeningBalance` сверяет `expectedRevision`, если она есть, и увеличивает ревизию. Новая `setCardRate(executor, id, { rateMinor, currency }, expectedRevision, context)` — узкая правка пары ставки (пара null вместе, как CHECK), обязательная ревизия, другие поля не трогает. `createCard` и `importCard` не меняются (ревизия 1 по умолчанию).

Маршруты (`students.ts`): PATCH `/:id` разбирает `updateStudentRequest`; archive и restore читают необязательное тело `cardRevisionRequest` (пустое тело — как `{}`, потому что web сейчас шлёт POST без тела); `changed` → 409 `errorBody('precondition_failed', 'The student changed')`; opening-balance — то же.
