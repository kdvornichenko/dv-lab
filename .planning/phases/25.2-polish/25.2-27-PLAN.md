# 25.2-27 — Api: push — планировщик и отправка

<objective>

Конфиг VAPID, подписки, настройки «что уведомлять», сигнал присутствия (`isPresent`), строители адресов `links.ts` и локальную пару VAPID сделал 25.2-15 (исходный план разделён: 17 файлов больше предела в 15); таблицы `push_deliveries` и `push_payment_alerts` — 25.2-01. Web — 25.2-25 (service worker показывает пришедшее) и 25.2-26 (карточки, клиент подписки, сигнал присутствия).

Решения по своему усмотрению (RESEARCH 6): планировщик — тик раз в минуту в стиле `createHousekeeping` (не pg-boss): один процесс api, повторы при перезапуске и наложении контейнеров на выкатке отсекает уникальный ключ `push_deliveries`. Подавление на переднем плане — на сервере по сигналу присутствия того же устройства (A8, `isPresent` из 25.2-15), потому что Safari отзывает подписку после трёх push без показанного уведомления. Вторая зона для текста урока («18:00 VN · 14:00 MSK») берётся у подписки (её присылает устройство). Деньги в текст уведомления не входят; адрес перехода — только фиксированные слова и непрозрачные id.

VAPID-ключи прода — шаг Server guy (user_setup, не задача исполнителя). Для локальной проверки — пара в `.env` и `.env.test` из 25.2-15.

Executor model: opus (фоновые задачи, внешний сервис, секреты, сервер).

Purpose: учитель узнаёт о скором уроке и о том, кому скоро платить, не держа приложение открытым.
Output: `push/scheduler.ts`, `push/deliver.ts`, подключение в `server.ts`, имена VAPID в `deploy/env.example`, разделы `lessons`, `payments`, `suppress`, `delivery` в `push-api.mjs`.
