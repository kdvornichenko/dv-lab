# 25.2-13 — Api: ревизия заметок и словаря

<objective>
Построить ревизию заметок и словаря (D-26, CS-95-97) поверх блоков с ревизией (25.2-04), квитанций заметок (25.2-11) и реестра (25.2-07). Ревизия — отдельный режим хода по образцу `/essay`: свой набор инструментов (чтение всего и одно применение итогов), запрет прочих записей, запись всего итога одной транзакцией с одной квитанцией kind `note` и общим Undo, дата ревизии в `note_reviews` (не в `students`, иначе все открытые предложения по карточке станут stale — Pitfall 7). Вопрос «Run a new one?» — строка `chat_actions` kind `change` с операцией `review_offer` в отдельном сообщении ассистента.

Решения по своему усмотрению: ревизия запускается встроенной командой `/review` с одним упоминанием ученика (как `/essay`; в меню команд её нет). Yes на вопросе подтверждает `review_offer` (состояние applied) и web отправляет `/review @ученик` тем же путём, что follow-up; Review now в профиле открывает новый чат с параметром, по которому web один раз отправляет ту же команду (web — 25.2-16). Ревизия сама исправляет дубли и опечатки и вливает старые «Added notes» в блоки; конфликты только перечисляет.

Executor model: opus (поведение модели, запись многих блоков одной транзакцией, Undo).

Purpose: заметки, которые копились из чата и рук учителя, периодически приводятся в порядок без потери текста.
Output: `review.ts`, `note-reviews.ts` (запись), блоки `review_offer` и `review_result`, `chat-review.mjs`.
</objective>
