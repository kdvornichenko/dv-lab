## Как проверяется отправка

Поддельный push-сервис на https не поднимался: `createWebPushDeliver` принимает необязательную функцию `send` (по умолчанию `webpush.sendNotification`), раздел `delivery` подставляет функцию, которая отвечает 201 или бросает ошибку с `statusCode` 410, 404, 500 и с endpoint в тексте ошибки. Проверено: в `send` уходят `vapidDetails`, `TTL: 600`, `timeout`; 201 → `last_success_at`, 404 и 410 → `revoked_at` и подписка пропадает из `activeSubscriptions`, 500 → `failed_at`, подписка остаётся.

Сеть до push-сервиса: `web-push` шлёт через `https.request`, который не следует редиректам (3xx возвращается как ошибка со `statusCode` и пишет `failed_at`); `timeout: 10000` — сокетный таймаут библиотеки, по нему запрос обрывается. Ответ сервиса клиенту не возвращается и в лог не пишется.

Планировщик в api: раздел `delivery` запускает второй api (порт 4272) с `NODE_ENV=development` и базой `dvlab_test` без `--env-file` — с парой в логе есть `push scheduler started`, без пары нет; основной api проверки (`NODE_ENV=test`, с парой) планировщик не запускает. Первый тик идёт через минуту после старта, процессы проверки живут меньше.
