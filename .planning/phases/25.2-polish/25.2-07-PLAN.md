# 25.2-07 — Api: реестр инструментов чата (ARCH-A3)

<objective>
Углубить реестр инструментов чата (ARCH-A3) до планов, которые добавляют инструменты (25.2-09: правка Details и поиск по календарю; 25.2-11: заметки и словарь; 25.2-13: ревизия). Сейчас одно новое действие требует 8-10 правок в разных местах `tools.ts`, `runs.ts`, контракте и web; JSON-схема пишется рядом с zod вручную; режим только для чтения у `/essay` решает по набору `WRITES` и префиксу `propose_`, поэтому пишущий инструмент с другим именем пройдёт запрет. После плана инструмент — одна запись; разрешение в режиме только для чтения — по объявленному действию.

Попутно (D-20, CS-108): блоки `suggestions` не попадают в историю для модели (строка в `runs.ts` около 173); схема `chatSuggestionsBlock` в контракте остаётся. Правило шага в реестре готовит имена учеников в шагах `propose_*` (CS-37, CS-57); слова шагов в web делает 25.2-12.

Поведение чата не меняется: это переделка без новых функций.

Executor model: opus (переделка центрального модуля чата без изменения поведения).

Purpose: три следующих api-плана добавляют инструменты одной записью, без риска обойти режим только для чтения.
Output: `tool-registry.ts`, записи инструментов в `tools.ts`, выведенные наборы, проверки в `chat-tools-schema.mjs`.
</objective>

`tool-registry.ts` (новый): тип записи `ChatToolEntry` — `name`, `description`, `input` (zod-схема объекта), `properties` (JSON-свойства), `optional` (список необязательных ключей), `strict` (boolean), `effect` (`'read' | 'show' | 'write' | 'propose' | 'page' | 'feedback'`), `step` (правило шага: какой вход несёт `student_id`, какой — имя для поиска, какой — период `from`/`to`, или `null` для инструмента без шага), `run` (исполнитель, получает контекст и уже разобранный вход). `tools.ts`: каждый существующий инструмент (`find_students`, `student_facts`, `student_notes`, `lessons`, `lesson_dates`, `mark_lesson`, `add_note`, `add_comment`, `propose_*`, `student_payments`, `open_page`, `essay_feedback`) — одна запись реестра, описания и JSON-свойства переносятся без изменения текста и порядка. Действие: чтения — `read`, `student_facts` и `lesson_dates` с показом — `show`, `mark_lesson`/`add_note`/`add_comment`/`propose_lesson_change` — `write`, остальные `propose_*` — `propose`, `open_page` — `page`, `essay_feedback` — `feedback`. Массив записей реестра экспортируется из `tools.ts` (имя — на выбор исполнителя, записывается в SUMMARY): его импортируют `chat-tools-schema.mjs` (Task 2) и `chat-runs.mjs` (сверка списка инструментов с реестром в 25.2-09). `CHAT_TOOLS`, набор strict и набор пишущих выводятся из записей; `WRITES`, `STRICT_TOOLS`, `changesData` и ветвление по именам в `runTool`, `read`, `write`, `changeRequest` заменяются вызовом `run` записи (чтения по-прежнему в `readSnapshot`; общий порядок проверок `runTool` — неизвестный инструмент, режим эссе, разбор входа — сохраняется). В режиме эссе разрешены только записи с `isReadOnly`, иначе прежний отказ `read_only_essay`.

`runs.ts`: `stepOf` берёт правило шага из реестра вместо проверок по именам (имя ученика по `student_id`, запрос `find_students`, период `lessons` и `lesson_dates`); набор инструментов хода эссе — из реестра. Блок `suggestions` в истории для модели больше не превращается в текст (ветка `case 'suggestions'` убирается, блок пропускается), `chatSuggestionsBlock` в контракте не трогать.
