# 25.2-15 — Api: push — конфиг VAPID, подписки, присутствие, настройки уведомлений

<objective>
Первая часть серверной стороны push (D-40, CS-109-111) — всё, с чем говорит браузер: конфиг VAPID, подписки устройства, строители адресов перехода, настройки «что уведомлять» в аккаунте и сигнал присутствия. Планировщик «скоро урок» и «скоро платить», подавление присутствием перед отправкой и отправку через `web-push` делает 25.2-27 (исходный план разделён: 17 файлов больше предела в 15). Таблицы и колонки настроек сделал 25.2-01; web — 25.2-17 (manifest, иконки, исключения proxy), 25.2-25 (service worker, переход по тапу) и 25.2-26 (карточки Settings, клиент подписки, сигнал присутствия).

Состояние «push не настроен на сервере» (`enabled: false`) и признак отзыва устройства api отдаёт в `GET /push/config`; рисует их карточка Settings в 25.2-26 (web, дизайн v102 п.116; в 25.2-24 Settings уведомлений нет).

Решения по своему усмотрению (RESEARCH 6): подавление на переднем плане — на сервере по сигналу присутствия того же устройства (A8; в памяти процесса, перезапуск безвреден), потому что Safari отзывает подписку после трёх push без показанного уведомления; этот план принимает сигнал и отвечает `isPresent`, планировщик 25.2-27 зовёт его перед отправкой. Вторая зона для текста урока («18:00 VN · 14:00 MSK») приходит с устройства при подписке и в сигнале присутствия и хранится у подписки — вторая зона живёт только в браузере. Адрес перехода — только фиксированные слова и непрозрачные id.

VAPID-ключи прода — шаг Server guy (user_setup в 25.2-27, не задача исполнителя); этот план работает и без них (`enabled: false`). Для локальной проверки исполнитель генерирует разовую пару в локальные `.env` и `.env.test` (файлы вне git) скриптом из рабочей папки сессии, ключи не печатает; этой парой пользуются 25.2-27, 25.2-25 и 25.2-26.

Executor model: opus (секреты, доступ по сессии, контракт для web).

Purpose: устройство учителя подписывается на push, учитель выбирает, о чём уведомлять, а сервер знает, какой экран открыт на устройстве.
Output: `push/subscriptions.ts`, `push/presence.ts`, `routes/push.ts`, контракты `push.ts` и `links.ts`, настройки уведомлений, конфиг VAPID, `push-api.mjs` (разделы routes, links, settings, presence, config).
</objective>
