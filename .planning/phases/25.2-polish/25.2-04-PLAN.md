# 25.2-04 — Api: идентичность блока заметок (ARCH-A2), словарь Removed, последние комментарии

<objective>
Углубить блок заметок (ARCH-A2) до планов, которые его трогают (10 — UI, 11 — правка из чата, 13 — ревизия): сейчас блоков ровно шесть с закрытым перечнем `kind`, запись без ревизии, а удаление и откат устроены тремя способами. Один владелец `apps/api/src/cards/blocks.ts` даёт блоки со свободным именем, порядком, ревизией и мягким удалением (D-34, D-02); `terms.ts` получает Removed, Restore и стирание через 30 дней (D-02, CS-99); плюс чтения для Overview — дата ревизии (CS-95) и последние комментарии (CS-89). Схема уже есть (25.2-01).

Совместимость: существующие типы контракта (`StudentSection`, `studentSectionsResponse`, `SECTION_KINDS`) не меняются — web в этой же волне (25.2-02) и проверки фаз 22-23 (`chat-api.mjs notes`, `chat-web.mjs notes`) читают и пишут `/students/:id/sections`. Новые схемы только добавляются.

Решение по своему усмотрению: удаление слова учителем из Vocabulary остаётся физическим, Removed — только для чата и ревизии (RESEARCH A7; `removed_by = 'teacher'` в схеме зарезервирован).

Executor model: opus (CAS, мягкое удаление, совместимость с импортом и чатом).

Purpose: без ревизии и мягкого удаления блока правка из чата (11) и ревизия (13) могут перезаписать текст, который учитель правит в соседней вкладке, а Undo не на что опереть.
Output: `blocks.ts`, `note-reviews.ts`, маршруты блоков, Removed и комментариев, `notes-blocks.mjs`.
</objective>
