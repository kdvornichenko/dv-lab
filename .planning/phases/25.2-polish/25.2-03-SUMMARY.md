# Phase 25.2 Plan 03: Хронологический леджер, короткая форма остатка, нормализатор названий Summary

Один проход `studentLedger` в core даёт по каждому уроку вычет, остаток после, покрывающую оплату и признак «оплачен позже», а по карточке — последнюю оплату и начало периода «с последней оплаты» по правилу D-22; итог прохода совпадает со `studentBalance` на всех векторах.

## Что сделано

- `packages/core/src/balance.ts`: типы `LedgerPayment`, `LedgerLesson`, `LedgerEntry`, `LedgerLastPayment`, `StudentLedger` и функция `studentLedger`. Порядок: дата (оплата — `paidOn`, урок — `scheduleDate`), в один день оплаты раньше уроков, оплаты по `createdAt` и `id`, уроки по `startsAt` и `key`. Покрытие FIFO по минутам. Граница D-22 по остатку перед последней оплатой. `studentBalance` не менялся, новых импортов нет.
- `packages/core/src/lessons.ts`: третий необязательный аргумент `balancePhrase(..., { short })`; без него фраза прежняя.
- `packages/core/src/text-match.ts`: `titleText`, `titleKey`, `nameMatches` — перенос `plainText`, `searchKey`, `nameMatches` из `apps/web/lib/lesson-count-text.ts` без изменения поведения; строка регулярного выражения невидимых символов скопирована из исходника скриптом. Web-копия не тронута (её заменит 25.2-12).
- `scripts/dev-checks/ledger-core`: девять сценариев `p2 ledger 1..9`, короткая форма остатка, три сценария text-match, включая сверку с web-копией на 15 векторах.
