### Fade скроллера чата в Firefox
- На проде в Chrome fade есть, в Firefox нет. Причина: fade построен на scroll-driven animations (`@supports (animation-timeline: scroll())`, globals.css ~515), в Firefox их нет. Нужен запасной вариант для Firefox (и Safari до 26): тот же вид (fade сверху в покое/по прокрутке и снизу), без scroll-driven animations (например, класс по положению прокрутки из JS с mask-image). Касается всех `scroll-fade` и `scroll-fade-x` в приложении, не только чата.

### Count lessons: хотфикс (PR 39, вне фазы)
- Поиск без ограничения окна синхронизации: события берутся напрямую из Google за выбранные даты (новый read-only маршрут); баннер про окно убран. Диапазон ограничен около 400 дней. Окно синхронизации (8 недель назад, 53 вперёд) остаётся вопросом: расширять назад или нет.

### Поправка про fade
- В Firefox fade на других страницах есть везде, нет только на скроллере сообщений чата (прод, Firefox). Предыдущая запись про отсутствие scroll-driven animations в Firefox неверна как общая причина: причина специфична для чата. Искать в разметке скроллера сообщений (chat-screen.tsx: viewport со scroll-fade внутри ScrollArea, role="log", mt-auto у первого ребёнка); воспроизводить в Firefox.

### Fade в Firefox: итог
- Fade нет нигде в Firefox (владелец уточнил), в Chrome везде есть. Верна первая версия: scroll-fade опирается на scroll-driven animations (`@supports (animation-timeline: scroll())`), в Firefox они не включены. Владелец смотрит прод в Firefox, поэтому нужен запасной вариант для всех `scroll-fade`, `scroll-fade-x`, `scroll-divider` (маска и линии по положению прокрутки из JS или CSS без animation-timeline), с тем же видом. Предыдущую поправку выше игнорировать.
