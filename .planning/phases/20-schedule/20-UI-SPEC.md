Dialog form groups `gap-4`; label to input `gap-2`; two-column field rows `grid gap-4 sm:grid-cols-2`; page block gap `gap-4 md:gap-6`; table cell padding `px-4 py-2`.

Exceptions (component dimensions only):

| Dimension | Value | Where |
|-----------|-------|-------|
| Grid row | 14px (`0.875rem`) per 15 minutes = 56px per hour, 96 rows per day [A]. Derived time-scale unit, not layout spacing: 56px per hour is a multiple of 4 and 28px per half hour too; the 14px step only quantises block `top` and `height`. Kept at A's value because variant A is not changed without the owner's request | Week grid |

## Time and Date Display Rules

| Rule | Decision |
|------|----------|
| Grid zone | `Asia/Ho_Chi_Minh`, always [D-07]. "Today", the week's Monday and Sunday, the now line and "past" all use this zone through `Intl` with an explicit `timeZone`, never the browser zone or `new Date().getDay()` |
| Week | Monday to Sunday [D-10]; navigation moves 7 days; "Today" returns to the current week |
| Time | 24-hour `HH:MM` (`hourCycle: 'h23'`), `tabular-nums`; ranges with an en dash: "18:00–19:00" |
| Day label | `Intl.DateTimeFormat('en-GB', { weekday: 'short', day: 'numeric', month: 'short' })` gives "Wed 14 Oct"; the year ("Wed 14 Oct 2027") is added only when it differs from the current year in Vietnam |
| Date and time | `en-GB`, `{ weekday: 'short', day: 'numeric', month: 'short', hour: '2-digit', minute: '2-digit', hourCycle: 'h23', timeZone }` gives "Wed 14 Oct, 18:00" (verified in Node: `Wed 14 Oct, 18:00`). This en-GB day-first form is the one exception to 19's en-US `dateStyle: 'medium'`; `DateField` keeps its en-US "Oct 14, 2026" trigger text unchanged |
| Month title (`h1`) | `en-US` `{ month: 'long', year: 'numeric' }` of the week's Monday: "October 2026". A week spanning two months: "Sep – Oct 2026"; spanning two years: "Dec 2026 – Jan 2027" (en dash with spaces) |
| Week range (header description) | "6 – 12 Oct"; spanning months "28 Sep – 4 Oct"; spanning years "28 Dec 2026 – 3 Jan 2027". Empty week: "6 – 12 Oct · No lessons this week" |
| Second zone | One for the whole grid, chosen in the header, default `Europe/Moscow`, stored in `localStorage` under `dv-lab.schedule.second-zone` (value is an IANA id or `none`); an unreadable or unknown value falls back to the default. Nothing is written to the database [D-07]. The selector trigger renders after mount so server and client markup match |
| Zone captions | `Asia/Ho_Chi_Minh` is "VN", `Europe/Moscow` is "MSK" (project rule); any other zone shows its short offset from `Intl` (`timeZoneName: 'short'`, for example "GMT+1") and the city segment of the IANA id (underscores to spaces) in the selector list |
| Second-zone labels | Computed with `Intl` for each hour row, never by adding hours. When the second-zone date differs from the Vietnam date, the label gets a suffix "−1d" or "+1d" (for MSK, rows 00:00 to 03:59 VN read "20:00 −1d" to "23:00 −1d") [default] |
| Lesson length | Shown in minutes ("60 min") in the lesson dialogs; 19's "minutes are never shown" rule applies to balances only |
| Series phrase | "Every Wednesday at 18:00" in dialogs; plural weekday "Wednesdays" in sentences |
| Next lesson cell | The Date and time form in Vietnam time, no second zone, no relative words ("tomorrow"): "Wed 14 Oct, 18:00". No lesson: "None" (muted) |

**Schedule page.** `PageScroll` (+E3) > `PageHeader` (title, description, actions per the Copywriting Contract) > week frame. Failure: header `h1` "Schedule" and `ReadError`. Loading: header real, frame height as below, inside it `SkeletonTable rows={10}` with the frame's height [default]; the Today/arrow buttons are enabled so the teacher can leave a slow week, New lesson is disabled until the student list and the week have loaded.

**Week frame (`WeekGrid`).** Outer: `Elevated offset={1} shadowLevel={2} className="flex flex-col overflow-hidden rounded-2xl"` with the height from the Spacing exceptions; the ring, background and shadow live on this wrapper, never on the scroller [D-14].

1. Header row (outside the scroller, so it never fades): `grid grid-cols-[4.5rem_repeat(7,minmax(0,1fr))] px-4 pt-4 pb-2 overflow-y-hidden [scrollbar-gutter:stable]`. Column 1 is the corner caption ("VN", second zone caption; `text-caption text-muted-foreground`, right-aligned, bottom-aligned). Columns 2 to 8: weekday abbreviation (`text-caption text-muted-foreground`) beside the date number in a 28px circle (`text-body font-semibold tabular-nums`; today `bg-gcal-today text-gcal-today-ink`, others `text-foreground`).
2. Body: `min-h-0 flex-1 overflow-y-auto scroll-fade [scrollbar-gutter:stable]` containing one grid `grid-cols-[4.5rem_repeat(7,minmax(0,1fr))] grid-rows-[repeat(96,0.875rem)] px-4 pt-2 pb-4`. `scrollbar-gutter: stable` on both header and body keeps the day columns aligned with the weekday labels when a classic scrollbar is shown. Default 48px fade [D-14]; the body is far taller than 200px.
3. Hour axis (column 1, scrolls with the rows, inside the scroller): for each of 24 hours a 4-row cell; label two lines, right-aligned, `-translate-y-2`, `text-caption text-muted-foreground tabular-nums`: VN time, then the second-zone time at `opacity-70` [A]. Hour rule: a 1px line `bg-gcal-line` from column 2 to 8 [A remap of `bg-border`]. Day separators: `border-l border-gcal-line` on each day column.
4. Day columns: each is `relative`, spans all 96 rows; today's column also `bg-hover rounded-xl`. A click on empty column space (`event.target === event.currentTarget`) computes the slot from the pointer Y, snaps down to 15 minutes, and opens New lesson with that date and time. One handler per column, no per-slot buttons.
5. Blocks: `button type="button"` absolutely positioned in their day column from data (`top`, `height`, `left`, `width` via inline style; no per-row class tables like A's `ROW_START`). Height equals the lesson's own length, minimum 28px, clipped at 24:00 [default]. Overlap layout: group the day's lessons into clusters of overlapping time ranges (sorted by start, a cluster grows while the next start is before the cluster end, using the displayed end); inside a cluster each block takes the first free lane, and every block in the cluster is `1/lanes` of the column width with 2px gaps. All statuses take part in the layout [A]. Block: `rounded-lg px-2 py-1 text-left transition-colors overflow-hidden`, name `w-full truncate text-caption font-semibold`, second line `w-full truncate text-caption tabular-nums opacity-80`; focus `focus-visible:ring-2 focus-visible:ring-focus-ring`.
6. Now line: only when the visible week is the current week; inside today's column, `pointer-events-none absolute z-20 h-0.5 bg-gcal-now` full column width with an 8px dot (`size-2 rounded-full bg-gcal-now -ml-1`); `top` from the Vietnam time of day; re-rendered every 60 seconds, and at midnight the "today" column and circle move on.
7. Initial scroll: on first render with data, the body scrolls so that 08:00 sits 56px below the top edge (`scrollTop = 7 × 56 = 392px`), which is "scrolled to 08:00" [D-10] and keeps the 08:00 label and 08:00 lessons clear of the 48px top fade. Moving between weeks keeps the current offset [default]. Today does not reset it.
8. Columns are `minmax(0,1fr)`: below the desktop width the days squash and block text truncates; the frame never scrolls sideways and there is no `min-w-3xl` / horizontal scroller (a `scroll-fade` and a `scroll-fade-x` cannot share one element). A's `Agenda` is not built (phone layout is phase 23).

**Dialog bodies.** Every dialog of this phase wraps its fields in `ScrollArea className="max-h-[calc(100dvh-14rem)]" viewportClassName="scroll-fade max-h-[inherit] px-1 -mx-1"` (4px of inner padding keeps focus rings unclipped); `DialogHeader` and `DialogFooter` stay outside the scroller, so the fade never covers the buttons. Verify in the browser that the viewport honours the max height. New lesson with its warning Banner is the tallest case.

**New lesson dialog.** `Dialog size="lg"`, form `gap-4`: Student (full width `Select`, active students A to Z); row Date (`DateField`, no minimum) + Start time (`TimePicker`); row Length (`TextField`, `inputMode="numeric"`) + Repeats (`Select`, default Once); optional overlap Banner; optional error Banner; footer. Opened from an empty cell: Date and Start time prefilled from the slot, Student empty with initial focus. Opened from "New lesson": Date today and Start time the next whole hour in Vietnam time [default], initial focus Student. Choosing a student sets Length to that student's `defaultLessonMinutes` until the teacher edits Length; after that it is never overwritten. Overlap check is evaluated for the first occurrence only, against the lessons of that date's week, and ignores cancelled and moved blocks. On success: close, toast, refetch the visible week, keep the scroll offset. There is no general "edit lesson" dialog: student and length of an existing lesson do not change in this phase (cancel and add instead); moving is the Move dialogs.

**Lesson, move and series dialogs.** As tabulated above. Mutations refetch the week after success (no optimistic updates) [19]. Past lessons (start before now in Vietnam time) are read-only [D-05]. Series actions appear on future occurrences only. "Move this lesson" on a series occurrence creates or updates a `moved` exception; on a single lesson it changes the time in place.

**Students list.** Edits E4 to E8 plus: `Input type="search"` state is local (`useState('')`, not in the URL), shared by the Active and Archived panels, filtering the loaded cards by case-insensitive substring of `displayName` after `trim()`. The header description keeps the unfiltered "{n} active, {m} archived". "Next lesson" cell `tabular-nums`, left-aligned, header `px-4 text-body font-normal text-muted-foreground`. The existing row navigation and name link stay.

## Interaction Contract

- **Navigation.** Today, arrows, New lesson, the second-zone selector and the blocks are the entire interaction surface of the grid. Arrow keys do not move between grid cells; keyboard users create lessons through "New lesson" and open lessons by tabbing to blocks (DOM order: day by day, then by start time) and pressing Enter or Space. No other keyboard shortcuts [accessibility is not deepened, per project rule].
- **Dialogs.** Initial focus: first invalid or first empty field; safe button in End series and Cancel. Submit disabled and `loading` while pending, errors under the field on submit or blur, Banner for server failures, values kept on failure, Esc and outside click close unless pending, focus returned per the table above. Overlap warnings update live (`Banner` has `role="status"`) and never disable submit [D-09].
- **Role.** Teacher-only; a student account keeps landing on `/` [19].
- **Motion and theme.** Registry defaults only; no custom animation for blocks or the now line (the line moves on its 60-second tick). Everything is checked in light and dark, including the dashed border of moved blocks and the gcal tokens.
- **Scroll fade.** Page body (`PageScroll`), week body, dialog bodies, the second-zone and student `Select`/`Combobox` lists (already fade), the `TimePicker` lists (24px) and the students table container (`scroll-fade-x`, 24px) all use the library classes. Pitfalls: ring or background on a wrapper, header outside the scroller, `viewportClassName` for `ScrollArea`, no copy of shadcn's `scroll-fade` utility, no static fallback fade, input and textarea excluded [D-14].
- **Data.** Occurrences of series are expanded by one pure `packages/core` function that the grid, "Next lesson" and (later) phase 21 and Google sync share; the UI never expands series itself. The week request covers Monday 00:00 to next Monday 00:00 Vietnam time.
