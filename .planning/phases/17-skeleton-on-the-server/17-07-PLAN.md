apps/api/src/lifecycle.ts (D-09) — по примеру lifecycle.ts из Code Examples, с разделением создания и подключения, чтобы app мог получить isStopping до старта сервера: тип Closable { name, close(): Promise<void> }; createLifecycle({ deadlineMs, logger, exit }) возвращает Lifecycle { isStopping(), manage(handles), shutdown(signal) }. manage({ server, resources }) запоминает сервер и ресурсы и подписывается через process.on на SIGTERM и SIGINT (именно on, не once: повторный сигнал не должен включить поведение по умолчанию и убить процесс). shutdown(signal) идемпотентна: второй вызов возвращает тот же промис. Порядок: флаг stopping; лог shutdown start с полем signal; жёсткий таймер на deadlineMs (unref) пишет shutdown deadline exceeded и вызывает exit(1); server.close с ожиданием колбэка; server.closeIdleConnections(); таймер на половину срока вызывает server.closeAllConnections(); после закрытия сервера ресурсы закрываются по порядку, ошибка каждого пишется в лог с полем resource, остальные закрываются; лог shutdown complete; exit(0). Сигналы и сроки больше нигде не обрабатываются.
