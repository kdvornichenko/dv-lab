Эта таблица задаёт presentation states, **не новый wire enum**. Safe DTO и операции связаны с R9 P1–P3 через F01/F02. Не выводить состояние из timer браузера, успеха POST или просто connected grant.

| Ось                   | Наблюдаемый факт                                            | UI                                                                                               |

| Notification delivery | Server подтверждает действующий channel для текущего target | Live updates / On; не означает newest event data                                                 |
| Notification delivery | Server подтверждает gap/renewal failure                     | Live updates / Delayed; последний подтверждённый вид и freshness сохраняются                     |
| Notification delivery | Disconnect/reconnect/stop                                   | Live updates / Paused; доступные действия из Phase 24                                            |

| Complete read         | Известен успешный полный check                              | Last full check / абсолютные date, time, zone; только confirmed timestamp, не время notification |
| Complete read         | Первый full sync или 410 resync действительно идёт          | A full check is running; предыдущий complete timestamp остаётся рядом, если существует           |

Watch failure сам по себе не задаёт write capability: fresh complete view может иметь отдельное разрешение сервера. Любой Save/gesture/review decision проверяет соответствующее server capability; Last full check/On не открывают запись. Во время неполного resync старый view остаётся read-only по R3. Successful complete reconciliation публикует один revision; прежние списки нельзя смешивать с новым неполным snapshot.

Nightly reconcile выполняется сервером при закрытой странице. UI показывает факт running/completed/failed из DTO, не часы обещанного запуска. Нет Sync now, progress percentage, UI countdown, fixed delivery SLA или обещания instant sync. Refresh и visible polling читают разрешённый safe status/view по F01/F02; GET не создаёт decision и не становится Google writer. Частота polling не доказывает freshness. R9 использует 90s только как существующий E2E budget, без provider SLA.

## 5. Events to review и решения — UI2

### Matching и список

Server сопоставляет app-created event с прежним lesson identity до name matching. Browser не разбирает title, recurrence или provider IDs. **UD2, unreviewed default**, связанный с R9 P4/F04: short name означает весь текущий card displayName. normalizeDisplayName нормализует whitespace; равенство нормализованного title и полного displayName — CASE-SENSITIVE. Только один exact match среди active cards допускает новый auto/explicit binding. First-word, prefix, fuzzy matching и lowercasing отсутствуют; duplicate exact names остаются review. Existing ID binding сохраняется после rename/archive и не переключает ученика. На open view refreshed binding заменяет прежний external block, не добавляет второй.

Review показывает unmatched или ambiguous **подтверждённые текущие** events. Server определяет границы/пагинацию списка, canonical identity/version и допустимые действия (F03/F05). UI не называет загруженную страницу полным списком. Empty допустим только при достоверном complete review result; paginated empty page не означает Nothing to review. Для большого списка сохранить page scrolling; Load more со stable server cursor — только если handoff предоставляет пагинацию, без фиктивного total.

Строка: plain-text title или Busy по safe DTO, полная дата и TimePair, видимый scope P19, затем Select Assign to a student и Ignore. Этот же scope показывается в существующих read-only details. Scope находится рядом с time, до controls в visual/reading order; он не скрыт в tooltip, Select или результате действия. Без provider IDs, email attendees, description HTML, conference links, private journal. Несвязанный event открывает Phase 24 read-only details; внутри controls click не открывает detail Dialog. Loading/error никогда не показывают старую строку как актуальную writable.

Scope поступает из versioned safe GoogleReviewList DTO R9 P5/F05. Presentation labels P19: Event для single, This occurrence для instance, Series для master family. Это подписи UI, не wire enum. Instance decision затрагивает только это вхождение; master decision — будущие members той же family. UI не выводит scope из title, recurrence или наличия siblings и не выбирает whole series за instance. Если scope неизвестен, Select и Ignore disabled; P17 объясняет причину и предлагает Refresh event. Известный scope с unavailable Assign сохраняет допустимый Ignore по отдельной capability.

**UD3, unreviewed default:** выбор ученика в существующем Select является явным Assign, как в v40; новый Save/confirmation dialog не добавляется. До выбора/commit scope уже виден в row/details; нужны актуальные identity/version/scope/capability. Игнорирование — supporting action без confirmation: Google event не удаляется. Обе операции сохраняют row до подтверждённого результата; общий request не повторяется при двойном click. Assign/Ignore создают только локальный binding/disposition, без Google PATCH.

All-day/unsupported duration/type имеют явную причину и unavailable Assign. Cancelled/deleted/historical-only не допускают нового Assign; history сохраняется.

Ignore действует по stable identity и scope R9 P4/P5/F06: title/time edits, 410 и reconnect к тому же account/calendar его не сбрасывают. Master Ignore охватывает будущих members того же master; instance Ignore относится только к этому member. Новый event/master identity — новый candidate. Provider data и transparency остаются прежними. Immutable requestId/body и CalendarReview.readDecision восстанавливают тот же outcome после lost reply до retry. Reload не восстанавливает draft selection и не повторяет мутацию. Undo/reassignment не добавляются.

## 6. Google wins и общий read-only view — UI3

После принятого server sync показывать Google calendar facts. Не вводить compare versions, Keep local, restore old time, resolution voting или optimistic duplicate. Changed/deleted external facts не удаляют физически локальные lessons/series/marks/history; ownership и eligibility из R3. Automatic mapping не создаёт Done/No-show или списание само по себе. Видимость отменённого lesson и сохранённой history использует существующие правила.

| Случай                                   | UI и подтверждение                                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Внешнее изменение при открытом календаре | Принять complete confirmed projection для того же target/range; сохранить выбранную неделю, scroll и focus; не success toast за каждую notification                      |
| Dirty lesson form стала stale            | Phase 24 external_change/precondition copy, in-memory inputs сохраняются; Save закрыт до fresh version/read и нового явного действия; draft не overwrite и не autosubmit |
| Outbound command ещё unresolved          | Phase 24 pending/unknown/recovery и barrier остаются; Google changed event не доказывает applied этой команды; результат связывается с её identity/revision              |
| Перенос одного Google occurrence         | Ровно одно актуальное вхождение, остальные без изменения; lesson details и mark linkage следуют server identity                                                          |
| Перенос Google series                    | Обновлённая series и нужные instances без duplicates; browser не меняет rule zone или instance keys сам                                                                  |
| Google delete/cancel                     | Активный calendar view следует confirmed Google result; сохранённая локальная history и marks не стираются; cancellation/history labels из существующего контракта       |
| Полный resync/потеря Google              | Последний complete view доступен для чтения с timestamp; новые calendar edits не принимаются; marks/balances только по Phase 24 local eligibility                        |

Schedule и Today/nextLessonAt после sync читают общего владельца confirmed projection. Следующий урок не берётся из review, partial sync или неподтверждённой команды. Если moved reference occurrence или marks меняют факт карточки, пересчёт выполняет существующий server owner; UI не вводит второе accounting rule.
