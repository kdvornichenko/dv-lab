# Правила исполнителя фазы GSD (общие для всех планов)

Читай этот файл первым. Номер фазы `N`, путь worktree `ROOT` (твой cwd) и план `N-NN-PLAN.md` даёт задание оркестратора.

## Где ты работаешь

- Worktree фазы `ROOT`, ветка `gsd/phase-N-*`. Из него не выходи.
- Другие исполнители правят этот же worktree одновременно (планы одной волны, непересекающиеся `files_modified`). Трогай только файлы своего плана и свой `SUMMARY.md`. Ошибка typecheck, lint или build в чужом файле принадлежит параллельному плану: повтори проверку через минуту, при повторе сообщи.
- Охрана корня перед первой правкой и перед каждым коммитом: `bash scripts/gsd/root-pin.sh <ROOT>` (код 0 и `ROOT_PIN_OK`; `FATAL` означает остановиться и сообщить).

## Коммиты

- Один атомарный коммит на задачу, только явные пути: `git add <файлы>`, затем `git commit -m "<сообщение>" -- <те же файлы>`. Без `git add -A`, `.`, `-a`, `--no-verify`, push, stash, reset, rebase.
- Сообщение: `type(N-NN): <одна строка по-русски, глагол в прошедшем времени, без точки>`, пустая строка, трейлер `Co-Authored-By: <модель> <noreply@anthropic.com>` (модель названа в задании).
- `index.lock` значит коммитит другой исполнитель: повтори через несколько секунд, лок не удалять.
- Последний коммит `docs(N-NN): ...` содержит только `SUMMARY.md`. `STATE.md` и `ROADMAP.md` обновляет оркестратор.
- `AGENTS.md` изменённый turbo: `git restore AGENTS.md`. `apps/web/AGENTS.md` создаёт `next dev`: удалить, не коммитить.

## Проект

1. Код без комментариев. Текст интерфейса только английский. Только Base UI, без Radix и cmdk.
2. Репозиторий публичный: ни адресов серверов, ни секретов, ни паролей, ни данных учеников (имена, суммы, заметки) в файлах, логах и SUMMARY. Vault только на чтение. В проверках используй вымышленные карточки `Alex Example NNNN`; в SUMMARY только счётчики и хеши.
3. Новых юнит- и интеграционных тестов нет (директива владельца 2026-10-09); e2e-тесты разрешены с 2026-10-10 и пишутся только планом, который их прямо называет. Существующие остаются зелёными; свой ломающий тест чини минимально. Приёмка: typecheck, lint, build, разовые скрипты, ручные шаги в браузере в обеих темах, SQL-счётчики.
4. `yarn install` запускает только план, который это прямо называет. Возрастной барьер Yarn (`npmMinimalAgeGate` 1440) не отключать.
5. База: dev Postgres 18 на домашнем сервере из `.env` и `.env.test` (`dvlab_dev`, `dvlab_test`; `dvlab_migrator` для DDL, `dvlab_app` для кода). Разовый SQL только через `node scripts/dev-checks/sql.mjs` (отказывает базам без суффикса `_dev` или `_test`). Фикстуры api и браузера: `scripts/dev-checks/api.mjs` и `web.mjs`. Для процессов с `--env-file` убрать `DATABASE_URL` и `MIGRATOR_DATABASE_URL` из окружения. Пароли и строки подключения не печатать.
6. `yarn workspace @dv-lab/api build` только в плане, где он назван (tsdown стирает `dist`). `yarn test` чистит `dvlab_test`: не запускать при параллельных исполнителях. `yarn knip` до итогового плана может быть красным.
7. Не больше одного web-плана в волне (общие `.next` и dev-сервер). Запущенные dev-серверы остановить и убедиться, что на портах 3000 и 4000 никто не слушает.
8. Дизайн ведёт отдельная сессия (Design dude): элемента нет ни в копии варианта A, ни в UI-SPEC фазы, значит остановиться и сообщить, свой вид не придумывать.
9. Не вызывать `gsd-tools query dispatch-isolation` и `worktree.*`: меняют состояние оркестратора.

## Ограничения оболочки (проверяет хук)

Хук изоляции отклоняет переменные оболочки, `$(...)`, heredoc, `sed -i`, `find -exec`, `git -C` и составные команды. Пиши простые команды, файлы правь через Edit и Write, многошаговое пиши скриптом в рабочую папку скриптов (`scripts/dev-checks` для общего, временная директория для разового) и запускай по пути. gsd-tools: `node ~/.claude/gsd-core/bin/gsd-tools.cjs <аргументы>` литералом, по одной команде.

## Прочитать перед работой

- `~/.claude/gsd-core/workflows/execute-plan.md`, `templates/summary.md`, `references/checkpoints.md`, `references/executor-examples.md`.
- Твой `N-NN-PLAN.md`, `.planning/PROJECT.md`, `STATE.md`, `config.json`, `CLAUDE.md`, `AGENTS.md`.
- `N-CONTEXT.md` (решения), `N-RESEARCH.md` (разделы, на которые ссылается план), `N-UI-SPEC.md` для UI-планов, `N-ARCH-REVIEW.md`, `N-SQUAD-REVIEW.md`, SUMMARY предыдущих планов, от которых зависит твой.

В конце порядок строгий: SUMMARY.md (по-русски), его коммит, и только потом отчёт. Рабочее дерево чисто по твоим файлам, процессов не оставлено.
